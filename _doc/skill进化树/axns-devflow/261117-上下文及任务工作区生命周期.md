## 十个要求场景的评估

以下“桌面推演”表示以具体输入检查规则如何决策，属于人工规则评估，未启动新模型窗口，也未测模型是否在真实任务中稳定遵循规则。脚本场景则调用实际 Node/Git，在临时仓库中断言结果；这仍不等于 Orca/DSH 实机联调。

| 场景 | 输入与评估方式 | 结果及限制 |
| --- | --- | --- |
| SI-010-1 大规模调查/实施 | 桌面推演：下一步调查多个认证入口，平台不提供剩余上下文。对照预算规则，先标“未知”；将只读调查与依赖该结果的实施分开，分别指定输入路径、服务/测试写范围、验证方法及整合者。 | 规则覆盖预算依据、拆分和最小摘要；不臆造容量或固定窗口数。新上下文执行及协调窗口实际体积未测。 |
| SI-010-2 同一任务换窗口 | 桌面推演最小交接字段；脚本用新格式 ID 登记、check、原执行者停写后 claim 交接，断言仅一个活动任务且路径不变。 | 交接字段覆盖授权、阶段、计划/状态入口、cwd/分支/提交、未提交差异、执行者/持权、证据和下一动作；脚本工作区复用通过。真实新模型恢复、未重跑有效阶段仍待原项目复验。 |
| SI-010-3 并行调查及后续实现 | 桌面推演：两个只读调查单元交出摘要，实施依赖调查结论，整合者复核最终差异。脚本覆盖不同 scope 并存、相交拒绝、共享文件 blocked、依赖未完成时 check 拒绝。 | 写权/依赖由真实 Git 夹具验证；明确作者自检不能冒充独立复核。真实多模型调查、摘要质量及最终整合待复验。 |
| SI-010-4 小型连续修改 | 桌面推演：只修改同一文档的两处连续说明，输入与输出规模小，无已知压缩信号。 | 规则允许当前窗口完成，不按 Todo 开窗，也不新增 worktree；未用模型批量评估遵循率。 |
| SI-010-5 工具不足/启动未知 | 桌面推演：指定 Orca 但入口不可调用时保留独立复核待办；可选端缺失时当前 Agent 继续已授权工作。平台桥测试模拟启动状态未知、超时/崩溃、重复回调及并发互斥。 | 规则要求先核实安装与真实调用条件；启动未知先查询派发状态，不重复派发、不伪报成功。平台桥为模拟程序，未验证真实 Orca/DSH 安装、连接及并发限制。 |
| SI-011-1 批次完成合入释放 | 新增 typed task IDs 测试：登记有界批次，检查/提交证据，finish 合入配置的 main，断言 HEAD、归档、持权释放、工作区和任务分支删除。既有测试覆盖最新集成分支前移、dirty 拒绝及中断清理。 | 实际临时 Git 仓库脚本验证；main 是夹具指定分支，可配置 master，不强改本仓库分支。不能据夹具推定业务功能验收已完成。 |
| SI-011-2 下一独立目标新建 | 同一测试在前一批归档后再次自动登记，断言新 ID、新工作区、基于最新集成 HEAD；拒绝换标题复用旧日期/类型/序号，并跳过残留分支/工作区占号。 | 实际 Git/文件系统断言；不把 slots=2 理解成永远只有两个工作区。 |
| SI-011-3 同一目标恢复 | 新格式任务串行 claim 交接，断言原 ID/目录和唯一活动记录保留；既有 runner 测试覆盖中断与合法回调恢复。 | 脚本身份/持权及恢复机制测试；真实模型跨窗口恢复仍待验。 |
| SI-011-4 并行任务与整合 | 不同 scope 登记、共享文件互斥、scope 相交回滚、依赖图检查；计划/交接模板明确整合和汇报责任。 | 脚本验证协调机制，人工角色责任做静态检查；未运行真实多平台并行开发。 |
| SI-011-5 记录不冒充实施 | 桌面推演：只收集“未来技能建议”时，进化记录保留待用户评审；记录批次交付不能写成技能修复，批准后另开独立实施任务。核对独立技能的评审和复验规则。 | 规则覆盖；来源项目原台账未改。收到本批差异后可回填“用户已更新待复验”，真实复验前不能填“复验通过”。 |
