## 事实与需求

用户反馈：模型选择过程中出现受限模型查询被当作完整目录、选项窗口与需求不匹配的情况；用户要求由自己预设并选择场景。检查源码与当前安装副本时，两者文本内容一致。技能原文要求按任务目标与风险选择场景，但没有强制 Agent 等待用户确认；该措辞允许 Agent 自行选择。此前答复又错误地称技能里没有相关规则，并对项目模型配置作出缺乏核实的结论。

## 预期与边界

正式开发开始前展示实际生效的用户预设和相关场景；Agent 可以推荐，但未获用户明确选择不得开始模型路由、正式计划或派发。明确的本轮选择、项目内明确授权的固定路由不重复询问。配置缺失/冲突、模板草稿和渠道可用性需分别说明；不把局部查询结果说成完整目录。

范围限于 `axns-devflow` 的模型交互提示和参考文档，不修改模型配置格式、脚本、用户项目配置或执行器。

## 候选改进与验收场景

- 新任务且存在有效预设：展示预设和相关场景，给出建议并等待用户选择后才进入正式阶段。
- 用户已在本轮指定场景：复用现有预设并执行，不重复询问。
- 配置缺失、冲突或含未知可用性模型：报告已核实路径、配置事实和缺口，不猜测、不静默回退。
- 初始化模板：明确标记为草稿，不能当作用户已经预设或确认。
