# Devflow 模型配置使用说明

保留 Orca 作为主要执行层，模型表按开发场景选择模型。配置页面已经加入实际保存能力。

在本仓库启动：

```powershell
npm run models:page
```

打开命令输出的本地地址。页面沿用项目已保存的活动预设；本项目当前使用“混合智能体团队”。需要按计划、实现、基础任务分工时，在“应用方式”选择“dsh&Orca”，检查实际模型ID后保存。下表为本项目常用模板中 dsh&Orca 的当前分配；通用模板与其他项目以其保存配置为准。

| 必备场景 | 模型默认值 | 推理强度默认值 |
| --- | --- | --- |
| 制定计划 | gpt-6.2-astra | high |
| 一般执行 | gpt-6.1-sol | high |
| 简单执行 | gpt-6.1-terra | high |

其他默认场景覆盖需求梳理、调试、重构、界面、测试、复核、验收、文档、资料归纳、交接和协调。页面提供数据库迁移、安全复核、前端实现、接口联调、部署准备五类项目场景，也能新增任意符合ID规则的场景。

模型名称是用户提供的可编辑默认值，保存没有验证账号的实际模型权限。Claude Code 渠道保留，填写已知模型ID并启用后可选。渠道、执行工具（CLI / 开发工具）、模型ID、推理强度分别配置。同一个模型需要不同强度时，建立两个模型条目再分别分配。

新项目：Devflow初始化开发流程时自动生成项目自己的 _plan/model-routing.json。旧项目：复用已登记的 model_config_file 或唯一项目模型表，保持原选择；缺少时创建，不修改其他流程记录。

```powershell
Set-Location D:/Coding/你的项目
node <扩展安装目录>/scripts/model-page.cjs
```

按项目类型复制个人默认配置：

```powershell
node skills/axns-devflow/scripts/init-workflow.cjs --project-root D:/Coding/新项目 --models-from D:/配置/前端项目模型.json
```

模板只在没有已有表时使用。项目专属配置修改不会回写个人默认表。引用共享绝对路径时，页面明确标识作用范围；需要隔离时复制表到项目内，并修改原 model_config_file 引用。

配置文件：[个人模型表](../model-routing.json)。详细规则：[技能使用说明](../skills/axns-devflow/references/model-routing.md)。页面入口：[模型配置页面](模型配置页面.html)。

保存只影响后续派发的新会话。编辑模型表不会开启自动执行，也不替换已有工单快照。Orca自动交接沿用已有控制器；本次验证针对配置与派发读取，没有把实际模型推理或业务自动交接冒充为通过。

## 配置中心编辑方式（2026-11-23）

配置中心依次为“模型配置”“项目开发配置”“场景&模型”“阶段与应用方式”“导入 / JSON”五个区域，桌面用顶部导航切换，窄屏用配置区域下拉框切换。导航和保存栏随滚动保持可见。

表单使用左侧标签。项目开发配置分为开关卡片、工作区与模型关联、自动执行入口；诊断信息在底部折叠，命令参数用多行 JSON 数组输入。先维护模型，再按场景分配。两张表的主要字段始终显示输入框，名称与配置 ID 分列；渠道、推理强度、擅长范围和图像识别等能力通过“设置”展开，场景使用边界在整行宽度的编辑区填写，说明随内容增高。模型和场景可按名称或 ID 搜索。修改模型配置 ID 会更新当前模型表里各预设的引用；自定义场景 ID 修改会同步阶段、预设和 DSH 子级场景引用。三个内置必备场景保留固定 ID，名称与说明可编辑。

模型的“图像识别”复选框保存为可选布尔字段 `supports_vision`，表示用户确认可读取图片。未标记不代表平台已验证不支持；此字段只记录模型能力，不改变模型 ID、权限或推理请求参数。

进入“阶段与应用方式”后，卡片展示各阶段的场景和对应模型；当前应用方式名称、说明可直接修改，也可复制创建项目预设。项目开发配置和模型草稿统一保存；任一保存按钮均写入同一份草稿，校验失败不写入，写入失败恢复原配置。

| 控制项 | 可选值与作用 |
| --- | --- |
| DSH 协作模式 | 关闭、普通子智能体、Team 智能体团队；场景可继承默认模式。 |
| DSH worktree | 沿用 DSH 原生配置、关闭、允许；控制新会话的原生 `create_worktree` 工具。允许后由调用创建，保存本身不创建工作区。 |
| 项目 worktree 隔离 | Devflow 项目任务隔离与集成分支设置，独立于 DSH 原生工具。 |

DSH worktree 保存为 `team.worktree`，可与 `team.enabled=false` 一起使用。场景未单独配置时继承预设的 worktree 选择；默认也未指定时沿用 DSH 配置。选择 DSH 模型后，展开场景行即可编辑协作和原生 worktree；非 DSH 行隐藏这些不适用的控件。

本机 DSH 0.2.2-rc.5 的 Team 已复用普通子智能体，并移除了旧 `maxMembers` 配置。合成器识别当前原生 Team 服务并使用 `defaultEnabled`，保留旧版实验性 Team 兼容。旧表带 `max_members` 时，在页面重新选择 Team 后保存以采用新版原生限制；新版不把旧人数参数当作已生效。已用本机 headless 配置验证四种协作/worktree 组合的合成结果，未启动真实模型会话。

### 项目设置与应用方式对比

- 项目开发配置中的执行适配器、关联工作区模式、关联模型预设使用带说明的单选项。选用命令桥时显示可执行文件和命令参数。选择工作区关联模式后显示可关联的预设。
- 集成分支下拉读取当前项目本地 Git 分支，并标记当前分支。可以在启用 worktree 隔离前选好并保存。删除或新建分支后可重新加载列表。远程分支需先有对应的本地分支才能选为集成目标。
- 点击“对比应用方式”查看各项的适用场景、已保存的方式说明、默认任务模型和单独配置的场景。适用场景和说明可在“阶段与应用方式”中编辑。适用场景保存为可选字段 `use_case`，旧模型表可直接打开，内置应用方式自带界面提示。
- 场景对照表在默认任务模型下显示实际模型 ID，随当前预设和默认模型选择更新。

浏览器实测见 [应用方式对比](应用方式对比预览.png)。

应用方式对比展示适用场景、开发工具及其绑定关系。Codex 和 Claude 方式分别限制为对应执行工具的模型，混合及 DSH 方式可选择全部模型；模型与场景选项显示模型 ID。项目开发配置中的自动执行入口独占一行，工作区及模型关联在下方分列。

新项目默认包含 Codex、Claude 和 DeepSeek 三个模型配置，默认模型配置 ID 不可修改或删除。手动添加的模型可在模型配置表删除；如果仍被某个应用方式、场景或 DSH 原生推理设置引用，需先移除或调整这些引用。删除后须保存模型配置。已有项目的模型不会自动清理。推理强度是模型配置项的参数；同一模型要在不同场景使用不同强度，可增加多个配置项并填写相同模型 ID、不同推理强度。

P5 默认关联“升级处理与人工裁决”场景，模型沿用当前应用方式的默认分配，可按场景调整。P5 仍等待人工裁决，不会因为关联模型而自动派发。


### 常用模板与能力匹配

已将本项目保存的模型、场景和应用方式快照写入 `skills/axns-devflow/assets/model-routing.personal.json`。进入其他项目目录后，执行 `node <技能仓库>/skills/axns-devflow-ext-autopilot/scripts/model-page.cjs --personal` 可从常用模板打开新项目草稿；保存后写入该项目自己的模型表。也可执行 `node <技能仓库>/skills/axns-devflow/scripts/project-models.cjs init --project-root <项目路径> --personal` 直接初始化。已有项目配置优先，不会覆盖。该模板是快照，后续修改本项目不会自动同步模板。

在场景行展开“编辑使用边界”设置编码、分析推理、图像识别、搜索、文档写作和代码复核要求；在模型行展开“设置”填写擅长范围描述并声明对应能力，图像识别复选框也收纳在此处，主表不再单列。分配列表展示匹配或待确认；未声明能力不等于模型不支持，搜索能力还取决于执行工具和权限。匹配为提示，不改变现有路由，也不验证实际调用能力。


### 配置联动与不关联模式

导航顺序为：模型配置、项目开发配置、场景&模型、阶段与应用方式、导入/JSON。模型配置只维护模型清单及参数。

项目中的“关联模型预设”和其他分区的“应用方式”共用模型表的 `active_preset`；从任意位置切换，会立即同步其他位置。保存按钮统一提交模型表与项目设置，并检测模型表、AGENTS.md、autopilot 配置和关联设置是否被其他窗口修改。

选择“不关联”后，场景&模型及阶段路由只读，已有分配保留。保存后不再加载关联的模型表参与路由，执行时沿用会话模型；重新关联即可恢复编辑。不关联不会关闭自动执行或工作区隔离，也不保证始终在同一窗口运行；这两项仍由项目开发配置及执行工具管理。导入/JSON 保留配置维护能力，但不关联时其路由不会参与执行。

通用模板和常用模板均已补充各模型的分工说明、擅长能力和全部场景的能力需求。常用模板保留本项目的 7 个模型及 18 个场景：计划角色侧重方案与复核，实现角色侧重编码与测试，基础角色侧重小改动与整理，资料角色侧重搜索与写作。这些是可调整的模板分工，不代表对模型效果的实测结论；既有模型 ID、推理强度、启用状态、图像识别声明和场景分配保持原配置。
