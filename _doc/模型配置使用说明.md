# Devflow 模型配置使用说明

保留 Orca 作为主要执行层，模型表按开发场景选择模型。配置页面已经加入实际保存能力。

在本仓库启动：

```powershell
npm run models:page
```

打开命令输出的本地地址。仓库已有的活动预设仍为 codex_only；需要采用新的三模型组合时，在“应用方式”选择“项目默认 · Astra / Sol / Flash”，检查实际模型 ID 后保存。

| 必备场景 | 模型默认值 | 推理强度默认值 |
| --- | --- | --- |
| 制定计划 | GPT-6.2-Astra | high |
| 一般执行 | GPT-6.2-sol | high |
| 简单执行 | DeepSeek-V4.1-flash | 留空，使用渠道设置 |

其他默认场景覆盖需求梳理、调试、重构、界面、测试、复核、验收、文档、资料归纳、交接和协调。页面提供数据库迁移、安全复核、前端实现、接口联调、部署准备五类项目场景，也能新增任意符合ID规则的场景。

模型名称是用户提供的可编辑默认值，保存没有验证账号的实际模型权限。Claude Code 渠道保留，填写已知模型ID并启用后可选。渠道、执行端、模型ID、推理强度分别配置。同一个模型需要不同强度时，建立两个模型条目再分别分配。

新项目：Devflow初始化开发流程时自动生成项目自己的 _plan/model-routing.json。旧项目：复用已登记的 model_config_file 或唯一项目模型表，保持原选择；缺少时创建，不修改其他流程记录。

```powershell
Set-Location D:/Coding/你的项目
node <扩展安装目录>/scripts/model-page.cjs
```

按项目类型复制个人默认配置：

```powershell
node skills/axns-devflow/scripts/init-workflow.cjs --project-root D:/Coding/新项目 --models-from D:/配置/前端项目模型.json
```

模板只在没有已有表时使用。项目专属配置修改不会回写个人默认表。引用共享绝对路径时，页面明确标识作用范围；需要隔离时复制表到项目内，并修改原 model_config_file 引用。

配置文件：[个人模型表](../model-routing.json)。详细规则：[技能使用说明](../skills/axns-devflow/references/model-routing.md)。页面入口：[模型配置页面](模型配置页面.html)。

保存只影响后续派发的新会话。编辑模型表不会开启自动执行，也不替换已有工单快照。Orca自动交接沿用已有控制器；本次验证针对配置与派发读取，没有把实际模型推理或业务自动交接冒充为通过。
