# Python、Vue 3 与 Tauri 的跨端架构

> 项目规范候选模板：使用前按当前项目事实裁剪，在项目基线中记录采用的规则和待定项。示例架构、界面布局、事务及迁移模式均需由项目确定。

## 技术选择先核实

不预设具体版本或框架。先读取 `pyproject.toml`、Python 锁文件、`package.json`、前端锁文件、`Cargo.toml`、`Cargo.lock`、Tauri 配置与启动脚本。已有 Quart/FastAPI、SQLite/PostgreSQL、组件库和状态方案按目标项目沿用。

新项目可从 Python 异步 HTTP 服务 + Vue 3/TypeScript/Vite + Tauri + SQLite 的桌面结构开始讨论；这是来源架构的可选基线，不自动添加所有依赖。使用框架或插件具体 API 前查目标依赖版本及官方说明，不凭本 skill 猜接口。

```text
Vue 页面/组件 → 领域 API → Python Route → Service → Repo → 数据库
                                 ↓          ↓
                              校验/响应   Provider/任务/审计
Tauri 窗口/本机命令 → Sidecar 启停、运行参数、健康检查、进程所有权
配置事实源 → 派生 Python 配置、前端公开配置、Tauri 运行配置
```

## 目录范例与边界

```text
apps/
  server/
    main.py
    module/<domain>/             # route/schema/service/repo，按现有结构安排
    external/<provider>/         # 厂商协议适配
    plugin/                      # 真正跨领域基础能力
    migrations/
    tests/
    pyproject.toml
  ui/
    src/api/<domain>/
    src/views/<domain>/
    src/components/              # 公共组件与领域组件按现有边界组织
    src/stores/                  # 仅跨页面共享状态
    package.json
  desktop/
    src-tauri/
      src/
      capabilities/             # 使用相应 Tauri 版本时核对
      tauri.conf.json
config/                         # 可选配置事实源与schema
```

目录以实际项目为准；不强迫迁移成熟目录。内部文件和公开函数沿用领域命名，新增/改名提前确认最终路径及调用方，同步导入、导出、动态引用和测试。外部序列化协议名与内部文件名分别处理。

## Python 实现顺序

1. 定义领域模型和 DTO：ID、可空、枚举/字典、数值类型、分页、时间和错误来源；跟随现行接口契约，不照搬来源项目响应包装。
2. Repo 负责参数化 SQL、事务和映射；Service 负责业务校验、外部适配、状态转换、任务和审计；Route 负责请求解析、输入模型、上下文与统一响应。
3. 异步服务中的阻塞 I/O/CPU 工作移出事件循环。长任务返回任务标识与真实状态，不让请求无限等待。
4. 统一异常和日志：保留诊断线索，向调用方返回可理解错误，不吞错、不造成功、不用假数据替代不可用 Provider。
5. 同步迁移、DTO、调用方、前端类型和领域文档；数据库及外部 API 事实只维护一份。

纯业务与 I/O 可分离以便测试；遵守目标仓库对 Repo/Service 的已有划分，不新增第二套平行架构。

## Vue 实现顺序

领域 API 与类型 → 公共组件/同类页面复用 → 交互与状态 → 真实请求与回读。页面通过统一请求层处理 URL、鉴权、错误和加载；不在多个页面拼服务地址或定义不同的同一 DTO。

状态值、ID 和日期等协议保持准确类型，尤其 `0`、`false`、空字符串、`null` 与“未提供”不得混淆。消费者可维护字典与固定代码协议分别管理；动态字典新增值不等于系统自动获得新执行能力。

## 配置单一来源

跨端参数有唯一所有者，生成文件标识为派生物。可以使用 TOML/JSON/profile 编译，也可复用目标项目已有配置方案，不强制新建工具。

| 参数 | 归属原则 |
| --- | --- |
| 端口、服务URL、Sidecar名、数据目录、跨端超时、应用版本 | 明确的共享配置源，经schema/校验派生 |
| 只影响前端的公开构建项 | 前端环境配置；不得放秘密 |
| 用户可修改的设置 | 既有设置存储，注明立即生效/重启生效 |
| 多实例领域数据、厂商连接历史 | 对应领域模型，不塞进任意全局键值表 |
| 文件私有实现常量 | 留在所属代码，不为“统一”抽成配置 |

明确合并优先级，例如测试显式覆盖 → 受控进程参数 → 允许覆盖的用户设置 → 当前环境 → 基础默认；具体顺序以项目契约为准。启动只初始化缺失设置，不重置消费者已保存内容。

开发、测试、打包使用明确 profile；如已有编译器，运行对应配置生成命令并检查所有消费者一致。禁止手改生成 JSON、临时 Vite env 或 Tauri 派生配置冒充修复。

## Tauri 与 Sidecar 生命周期

先确认 Python 作为托管 Sidecar、外部常驻服务还是开发进程。复用现有监督者；只在目标模式需要时增加实现。

- 开发期可由项目虚拟环境运行 Python；发布期按既有方案生成二进制（如 Nuitka），由桌面包纳入。不得把开发解释器路径写进发布配置。
- 将配置路径、数据目录和必要的会话参数受控传入子进程。仅本机服务按产品拓扑监听回环地址；本机通信鉴权沿用明确模式，不私自禁用。
- 启动检查端口冲突、子进程退出、健康端点和版本/协议匹配；健康检查需确认是本次拥有的服务，不能只凭端口可连接。设置超时和可理解错误，业务窗口在所需服务就绪后可用。
- 记录 PID/句柄和所有权；重载、退出、取消启动和启动失败只回收本任务/本应用拥有的进程树，不能杀未知占端口进程或按宽泛进程名清理。
- Windows 需要可靠子树回收时复用或评估 Job Object/监督者；退出有界等待和兜底，不把操作系统机制名当作已验证实现。
- 若同一数据库只能由一个应用服务执行迁移/恢复，先取得规范数据库路径对应的服务所有权锁，再进入生命周期；该锁不替代业务事务，也不应把所有 SQL 请求串行化。
- 本机文件/目录选择、路径打开、权限声明和插件命令在真实 Tauri 环境验证；浏览器 Vite 页面通过不能证明原生命令成功。

## 数据与发行目录

区分只读安装资源、Sidecar 和可写数据。便携版可采用 exe 同级 `data/`，安装版可采用应用数据目录或明确可写目录；由产品约定决定，以项目自己的目录策略为准。验证普通用户权限、非 ASCII/空格路径、搬移和升级保留数据。

发布时核对目标三元组、Sidecar 二进制命名、`externalBin`/资源清单、版本元数据与最终实际目录；具体键和值以锁定的 Tauri 版本和项目脚本为准。源码通过、开发桌面启动、打包成功和安装后运行是不同证据。
