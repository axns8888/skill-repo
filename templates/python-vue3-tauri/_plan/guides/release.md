# 数据库演进、备份与桌面发布

> 项目规范候选模板：使用前按当前项目事实裁剪，在项目基线中记录采用的规则和待定项。示例架构、界面布局、事务及迁移模式均需由项目确定。

## 先判断采用哪种机制

已有迁移框架和发行策略优先。来源项目采用 SQLite、应用版本包和开发中转；新项目可以借鉴，不要求先实现整套自研迁移管理器。以下不变量适用于相应迁移模式，实际命令从目标仓库发现。

## 数据库变更

1. 明确当前版本、目标版本、数据库所有者、结构/数据影响及与源码回退的匹配关系。禁止将生产库直接作为开发测试夹具。
2. 记录表/字段/索引/约束/种子、数据转换和默认值语义；同步 Repo、DTO、前端类型、调用方、文档与受管契约生成器。
3. 已执行迁移的身份、内容摘要及顺序保持稳定；修正通过新步骤追加，不重写旧步骤掩盖已执行事实。迁移与技术台账在明确事务边界内更新，失败不能留下假成功版本。
4. 在隔离环境验证新库初始化、旧版本升级、重复启动不重放、失败回滚、外键/完整性、数据语义和结构契约；覆盖范围按实际变更风险裁剪。
5. 结构变更未验收前需有与源码版本匹配、可实际恢复的原始备份。不要把只有表结构或部分表的导出写成“完整备份”。

SQLite 活跃库备份使用现有受支持的数据库一致性机制或完整逻辑导出；WAL 模式下不能只复制主 `.db` 就宣称完整。验证恢复后的结构、数据、索引/视图/触发器和完整性/外键；备份失败保留上一份有效文件。

## 可选的开发中转与正式包

目标项目采用此模式时保持以下语义：

| 状态 | 含义 | 下个动作 |
| --- | --- | --- |
| developing | 任务ID+序号标识的变更，供开发配置执行 | 隔离验证后提交摘要 |
| pending | SQL/迁移摘要锁定，等待人工验收 | 用户明确通过后记录依据 |
| accepted | 已通过但未进入所属正式包 | 按依赖/创建顺序合并 |
| merged | 保留原步骤身份进入所属未发行包 | 发行任务中冻结 |

开发中转不等于新应用发行号；同一未发行目标继续维护同一版本包。已经执行或已提交锁定的变更不改写，失败通过追加修正步骤处理。

合并保留步骤 ID 和摘要，开发库重启只核对台账，不重放 SQL；新安装从正式版本包各执行一次。中断重试不得重复追加。前置未合并时不得越序；多个版本的开发/测试库不来回降级复用。

自动测试不代替用户通过，不自动 accept/merge。发布配置拒绝其目标版本及前置版本的未合并变更，不能用 debug 开关绕过。未采用中转的项目使用现有迁移验收和发行机制，不创造不存在的 `stage/accept/merge` 命令。

## 统一版本与环境

如果多个组件展示同一应用发行版本，指定唯一版本源，派生 Python 健康信息、Vue展示、Tauri与Python二进制元数据和发行清单。包管理清单自身版本与应用运行版本可以职责不同，不为“统一”盲目全改。

区分开发、测试、打包配置以及数据库目标；生成配置不能成为第二事实源。已发行/冻结迁移包不可修改，下一真实版本由用户/项目策略确定，不由工具擅自猜号。人工验收通过本身不触发冻结、版本递增或公开发布。

## 日常验证与构建发布

| 任务 | 默认验证 |
| --- | --- |
| 纯文档/提示词 | 编码、相对引用、规则与状态一致性 |
| Python功能 | 相关测试/隔离库、必要静态检查、真实内部链路 |
| Vue功能 | 类型、相关交互、受改范围格式/样式检查 |
| 配置或Tauri源码 | 配置解析、目标源码检查及受影响原生行为；声明未验证部分 |
| 明确构建/打包/发布任务 | 按依赖顺序构建并检验真实产物，不沿用旧产物结论 |

不把前端生产构建、Python打包和Tauri安装包作为普通改动的机械收尾。进入发行任务后完成必要构建；已有授权不重复询问，外部分发按用户授权执行。

## 构建任务检查顺序

1. 核对受测源码/dirty内容、依赖锁文件、目标平台/架构、profile、版本、迁移状态、可写目录和输出位置。
2. 按仓库脚本派生配置，生成本次前端资源与 Python Sidecar，再组装 Tauri；具体先后跟随真实构建依赖，记录每项产物来源。
3. 核对 Tauri `externalBin`、架构命名、资源、配置及权限/插件。锁文件或权限声明变化按范围补验证。
4. 检查主程序与 Sidecar 的版本、哈希/来源、实际目录和启动入口。脚本/元数据 dry-run 只证明参数，不声称 EXE 已生成。
5. 按交付形态验证安装/便携启动、普通用户写权限、空格/中文路径、数据保留、升级与退出回收；真实第三方按已有授权和可用环境处理。
6. 记录未签名、未安装测试或未分发等实际状态，仅报告与本次交付相关的限制；不把“包生成”写成“用户验收通过”。

若 Sidecar 源码在构建后又修改，旧包不包含该修改。重新生成受影响产物并复核来源，或明确交付只是源码改动。

## 回退

回退计划说明源码、配置、数据库与产物的配套版本；不能只回滚前端留下新 schema。恢复先在隔离副本证明可行。现役停止、恢复、覆盖或删除只在既有授权目标内执行；确认可恢复并不构成执行现役恢复的授权。
