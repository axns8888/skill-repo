# 服务端批量操作契约

> 项目规范候选模板：使用前按当前项目事实裁剪，在项目基线中记录采用的规则和待定项。示例架构、界面布局、事务及迁移模式均需由项目确定。

适用于批量新增、编辑、删除、发布、撤回、启停、导入及其他会改变业务状态的操作。项目明确采用本契约后，执行以下约定；分页读取、任务状态查询不属于批量写请求。

## 采用服务端批量入口时，前端一次提交

一次用户确认只调用一次服务端批量入口，提交稳定 ID 集合与操作参数。禁止前端通过 `for`、`forEach`、`map`、`Promise.all`、并发池或分片多次调用单项写接口；也不能先调用多次再拼成一份“批量结果”。没有批量接口时补服务端实现，不能降级。

集合超过上限时返回明确限制，或将完整范围一次提交给服务端任务；不在客户端自动切片。若数据规模必须上传文件或传递查询快照令牌，先设计稳定选择范围和后端批任务契约，不用传输分片伪装成多次业务写入。

提交期间按既有请求层防重复，结果、失败原因和进度以服务端为准。取消确认不发送写请求；超时重试须遵守明确的幂等契约，不盲目重放已有副作用。

## 最小请求定义

沿用项目 API 路径、HTTP 方法、响应包装和 ID 类型，不硬编码本文件示例。对每个操作约定：

| 字段/规则 | 必须明确 |
| --- | --- |
| 操作 | 独立操作端点或服务端允许的操作白名单，禁止任意函数名执行 |
| 范围 | 稳定 IDs 或受控批量创建数据；ID格式、空集合、数量/大小上限 |
| 参数 | 允许字段、类型、缺省含义、跨字段规则 |
| 身份 | 继承真实上下文与权限，不信任前端传来的权限判断 |
| 重放 | 操作可能重复时的幂等键/冲突行为；仅按业务需要设计 |
| 结果 | 原子或部分成功、错误来源、计数、逐项明细或任务标识 |

## 服务端责任

1. 请求层校验操作、集合非空、单次上限、ID 格式和参数白名单；去重规则与结果计数口径明确。
2. Service 依据最新数据检查存在性、权限、当前状态及关联限制；不使用前端旧状态作为执行依据。缺失、已满足目标状态等分别定义失败或跳过。
3. Repo/领域方法按下面的事务语义执行；服务端内部允许逐项调用已有方法，不把逐项调度交回前端。
4. 写入领域审计：操作主体、稳定对象、操作、实际结果及可关联的批次/任务标识；返回错误不暴露堆栈、凭证和内部路径。
5. 外部副作用无法随数据库回滚时说明补偿或任务状态；不得宣称未经实现的跨系统整批原子性。

## 二选一的提交语义

| 方案 | 行为与返回 | 必测场景 |
| --- | --- | --- |
| 整批事务 | 任一必要校验/写入失败整批不生效；返回具体错误及影响范围 | 中间项失败后业务数据和事务内审计无部分提交 |
| 逐项独立 | 允许部分成功；明确成功/失败/跳过数量与逐项 ID、原因 | 一个失败不吞掉其他结果，计数与去重后输入一致 |

不得在实现中暗中混用两套语义。独立失败审计若需保留，应与业务事务回滚边界分别定义。长期任务返回真实任务 ID，以读取接口/事件查看进度和结果；取消行为及已发生副作用需有明确约定，页面不制造逐项进度。

## 必要验证

- 真实挂载事件或用户操作触发多选确认，断言一次且仅一次批量写请求、完整稳定 ID 和参数；取消为零次。选择状态、部分失败反馈和刷新结果正确。
- 测试跨越真实 Route → 请求模型 → Service → Repo/隔离数据库；只测按钮或替换整个 Service 不构成后端批量证据。真实第三方可用可控适配替身隔离，标注边界。
- 覆盖空集合、超限、重复/非法/缺失 ID、未知操作、非法字段、无权、状态变化与关联限制中实际适用项。
- 验证所选事务/部分成功语义、审计及真实回读结果；必要时覆盖并发冲突、幂等和任务取消。
- 同时提供“前端一次请求”和“后端完整批处理”两种证据，不能用其中之一替代另一项。

交付说明本次操作、真实端点、上限、去重规则、提交语义、结果口径、审计、任务化与未覆盖的外部边界。
