# 技能进化记录与评审交接

把工作中实际暴露的问题变成有事实、边界和验收条件的需求。可以单独使用，也可配合任何开发流程；不要求安装 axns-devflow、Orca、DSH 或启用 worktree。

## 收集

1. 从用户本次反馈和实际执行事实提取问题，区分用户要求、已观察现象、推测原因与改进建议。记录关联技能、实际加载路径/版本（不可得则未知）、触发任务及证据，避免把某项目特例扩成所有项目规则。
2. 在当前项目 `_doc/skill进化树/<技能名称>/YYMMDD-简明标题.md` 落盘，日期取当前本地日期。用 [需求记录模板](assets/need-record.md) 按需裁剪。复用同问题已有记录；同日不同问题使用可区分标题，不覆盖已有内容。不为每条普通实施 Todo 建文件。
3. 一个文件围绕一个可评审问题或紧密相关的一批需求；涉及多个技能时选主要责任技能，列关联项并用路径链接，避免重复的权威记录。无法确定责任技能时先在现有需求载体明确待归属，核实后归档，不虚构已安装技能名称。
4. 保存最小复现、预期结果和可观测验收场景。引用已有任务/证据，必要时脱敏；不复制完整上下文、凭据或无界日志。

## 移交与用户评审

交付标识为 `<技能名称>/<需求文件>`，例如 `axns-devflow/261117-上下文大小及新开窗口.md`，解析到项目 `_doc/skill进化树/` 下的对应文件。用户给绝对路径时读取该文件，保留来源；同名技能的源码库、已安装副本分别核实。路径必须在指定记录根内，不接受 `..` 或通过链接跳出该根的移交标识。

默认状态为“待用户评审”。**记录问题、移交文件、同意研究均不等于批准修改技能。须经用户评审决定批准范围、暂缓或拒绝，才实施对应技能变更。** 明确的“补上”“按本文实施”等指令已经构成相应范围的授权，不因流程再问一次。批准一部分只实施该部分；存在冲突先说明并遵循用户最新明确指令。

实施前读取目标技能及适用的技能创建规范，定位实际源码；默认修改用户指定的源码仓库。同步安装副本、远程推送、发布分别遵从用户授权，不因实施需求自动发生。当前只要求收集时，不改技能源码或业务代码。

## 有界实施与复验

收集批次写明本批问题、产物和停止条件；完成记录与移交即可结束该批，未来反馈另开批次。一个长期技能改进主题可以积累多个已关闭批次，不能用它无限延长同一工作区。

若项目采用任务登记/worktree，遵从其既有规则：本批完成后验收、合入指定分支、归档和释放；后续独立实施批次用新任务/工作区，同一未完成目标的恢复沿用原记录。不采用这些流程时无需为本技能引入它们。

实施结果记录源码身份或最终 diff、改动规则位置、验证方法/结果/限制。分别标明静态审查、脚本测试、模拟场景和真实平台验证。落地后状态可为“已实施待复验”；只有实际复验的证据才能改为“已复验”，不能把需求登记、文件生成、单元测试或用户收到补丁写成真实多窗口验证通过。原项目的反馈状态由具备实际证据的复验方更新。
