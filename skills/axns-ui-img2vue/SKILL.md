# 设计图转 Vue 3

默认由当前执行技能的智能体及其会话模型读取设计图、分析布局并编写 Vue 代码，使用宿主已有的图片查看、文件编辑、终端和浏览器能力。模型由宿主选择，不需要额外模型服务密钥、外部转换服务或转换器。

只有用户明确要求接入独立模型服务时，才依据用户提供的接口协议、地址、模型和鉴权方式处理；缺少必要信息时再询问。不预设厂商，不为支持自定义模型开发通用 SDK、代理或配置系统，也不默认安装或调用旧转换器。

以可验证的视觉实现为目标，不承诺像素级还原。截图不能证明接口、权限、数据流或操作结果已经实现；业务是否完成须以代码和实际验证为依据。

## 1. 确认任务与项目约束

- 读取目标项目适用的 `AGENTS.md`、相关目录约定、`package.json` 和目标页面及其依赖代码。确认 Vue 版本、JavaScript/TypeScript、组件库、样式方案、路由方式、包管理器与实际可用的验证命令。
- 遵守项目规定的工作流、工作区和修改范围。若并非 Vue 3 项目，不擅自迁移；先确认任务范围。只有输入缺失或冲突确实阻止实施时才询问，其余采用合理假设并简要说明。
- **新页面生成**：确认页面或组件的放置位置、入口和需要接入的布局。新项目可默认使用 Vue 3 Composition API 与 `<script setup>`；已有项目中新建页面仍沿用项目风格。
- **已有页面修改**：先理解原有接口、状态、事件、权限和路由依赖，保留已有正确业务逻辑，围绕设计差异做增量修改，不把原页面替换成纯演示页面。
- 综合用户文字要求、图片和现有代码：显式要求确定目标，图片提供视觉依据，现有实现提供业务事实。差异可兼容时保留业务并调整视觉；影响核心行为且无法判断时再澄清。

## 2. 实际查看并分析设计输入

- 使用宿主可用的图片查看能力实际读取图片，不仅凭目录或文件名推断。无法查看时，如实说明，向用户请求当前宿主可读取的图片或设计规格；不能声称已完成视觉分析。已获得文字规格时可以实施明确部分，并说明依据。
- 识别页面区域、层级、布局、对齐、间距、字体、颜色、边框、圆角、阴影、图片、组件及交互状态。区分截图像素尺寸、设备缩放与实际设计基准，不把截图宽度机械当作 CSS 视口宽度。
- 单图先确定它是完整页面、局部组件还是某个状态。批量图先按实际内容建立“页面—状态—目标文件—素材”的简要对应关系，可在会话中列出，不额外生成项目文档。
- 同一页面的正常、空白、加载、错误、弹窗等截图整合为同页状态；列表、详情、编辑等不同页面不能只因目录相同而合并。文件名用于辅助分组，最终以内容与项目导航关系确认。

## 3. 复用素材与项目能力

- 优先复用现有布局、组件、设计变量和素材。查找用户提供的 `assets`、`icons`、`images`、`sprites`、`cut`、`cut-images`、`切图` 等目录，也接受用户指定的其他位置。
- 同名素材原则上按页面级、模块级、全局级查找，再结合实际内容确认。保持素材比例与清晰度，按项目的导入、别名、静态资源或雪碧图规则引用，避免使用本机绝对路径。
- 不将整张截图当作页面背景冒充实现；不使用无关图标、emoji 或随意生成的图片替代已提供素材。缺少关键素材时说明差异，可用明确标识的临时占位，不宣称已还原。
- 优先沿用 Element Plus、Vant、Ant Design Vue、Wot-ui（uniapp、H5）等项目已有选择，也允许原生 Vue 与 CSS，不强制引入组件库。
- 使用 Wot-ui 时按项目实际安装版本和目标平台核对官方参考 `https://wot-ui.cn/llms-full.txt`；确认组件、属性和事件可用。uniapp 项目沿用其标签、平台能力和 `pages.json` 等页面配置，不套用普通 Web 项目的 DOM 或路由方案。其他组件库同样在需要时核对对应版本文档，不因参考文档提到工具链就额外安装。

## 4. 直接实施 Vue 代码

- 在用户指定范围内编辑代码，沿用项目语言、组件风格和样式方案，不默认增加 UnoCSS、Tailwind 或其他依赖。组件库用于承载合适的结构和行为，必要时补充 CSS 贴近设计，不机械套用默认外观。
- 批量实施前识别公共布局与组件；只有结构和职责确实可复用时才抽取，不能按“出现两次”机械拆分，也不为视觉相似强行统一不同业务。
- 页面和组件采用合法、可读、稳定的名称。中文设计名映射为有意义的代码名称，先检查现有文件和路由冲突，避免粗暴删除中文后得到空名或重名。
- 需要新增路由时融入现有路由结构或平台页面配置，仅增量修改相关项，不覆盖整个文件；用户只要求局部组件时不额外新增路由。
- 已有页面沿用真实数据和状态来源；新页面只有在已有接口约定充分时才接入。演示数据、占位内容和未接通行为须在适当的代码位置及交付说明中明确标识，不把模拟成功提示当作真实操作成功。
- 不从截图臆造接口、权限或复杂业务规则。正常、空白、加载、错误、弹窗等状态应由清楚的状态与触发条件控制；仅为展示而模拟的状态须说明，不能声称已经完成联调。

## 5. 处理尺寸与交互

- 以用户或项目指定的设计基准、最低分辨率和终端范围为准。未指定时结合截图和项目形态选择合理基准并说明；若桌面、移动端或多端选择会显著改变实现且无从判断，再询问。
- 不默认把所有页面转换成移动端 rem，不强制增加无关断点。按目标范围处理溢出、缩放、长文本和素材比例，保留项目已有响应式行为。
- 实现用户明确要求或设计明确表达的交互，如弹窗开关、标签切换、展开折叠、表单状态；已有业务操作继续使用其原实现。行为结果不明确时避免编造，说明待接通部分。
- 按实际元素与平台能力选择合理的语义标签、表单标签关联、焦点处理和键盘操作，不用不可操作的装饰元素冒充按钮。

## 6. 验证、校正与交付

- 检查实际存在的项目命令，执行与改动相关的类型检查、lint 或构建；记录命令和结果，不假设每个项目都有这些脚本。验证失败时先定位与本次改动的关系，修复相关问题并复验，不随意扩大修改范围。
- 宿主有可用浏览器能力且项目可启动时，遵守宿主与项目工具约定，在目标尺寸下打开页面、切换相关状态，与原图对比并修正主要差异。不硬编码某个浏览器工具。非浏览器目标使用项目已有的对应预览能力，H5 验证不能代替其他平台验证。
- 检查布局、字体、间距、素材路径、状态切换与控制台错误；验证已有页面修改未破坏原本正确的交互。代码检查通过不代表视觉验证通过。
- 没有浏览器、预览环境不可用、项目无法启动或接口无法联调时，如实说明已执行与未执行的验证及原因，不宣称已验证这些结果。
- 用户未要求时，不额外编写测试脚本或项目说明文档。交付时简要列出修改文件、实现的页面与状态、主要假设、实际验证结果及未接通行为；不把视觉还原描述为业务全部完成。

## 调用示例

以下路径相对于用户的目标项目，是输入示例，不是本技能附带资源。

**单图生成页面或组件**

```text
使用 $axns-ui-img2vue，根据 design/order-list.png 在 src/views/orders/ 下生成 Vue 3 订单列表页面。先读取项目约定，沿用已有组件库和样式，复用 src/assets/orders/ 的素材。目标桌面视口为 1440×900；没有现成接口的部分使用明确标识的演示数据，并说明未接通行为。完成后运行项目已有检查，有浏览器能力时对照原图校正。
```

**批量页面与状态整合**

```text
使用 $axns-ui-img2vue，查看 design/account/ 中的全部设计图，先按实际内容整理页面与正常、空白、加载、错误、弹窗状态的对应关系，再在 src/views/account/ 下实施。复用项目已有布局及 design/account/切图/ 的素材，只有结构和职责适合复用时才抽公共组件。沿用项目目标终端和页面入口配置，说明模拟数据与验证结果。
```

**按图修改已有页面**

```text
使用 $axns-ui-img2vue，对照 design/profile-new.png 修改 src/views/profile/index.vue。先理解现有实现，保留正确的接口、权限、表单校验及保存行为，只调整设计涉及的布局、样式和状态呈现。沿用项目当前尺寸与样式方案；完成后执行相关检查，有浏览器能力时检查视觉差异与已有交互，说明尚未验证的部分。
```
