# 执行路径与状态核对

## 任务与授权

开始时确认主机别名、目标环境、具体任务和资源范围；只有缺失信息确实阻断任务时才向用户询问。API/SSH 凭证不写入版本文件，也不经命令行参数传递。

以 [操作计划模板](../assets/operation-plan.template.json) 记录：目标状态、现状证据、计划路径、影响、回滚和验证方法。只读任务无需为每次读取请求重复授权。普通部署沿用已明确的任务授权；高危操作仍遵守 [安全规则](safety.md)。

## 路径 1：面板 API

以当前官方 [API 概览](https://docs.bt.cn/api/) 和具体模块说明为依据，先核对面板版本。不能把文档版本视作实际服务器版本，不能用任意面板路径做签名可用性探测。

现有诊断适配器只允许 `POST /system` 的三个 action：

| 操作 ID | action | 业务验证 |
| --- | --- | --- |
| system-summary | GetSystemTotal | 返回 CPU、内存、版本等已知字段 |
| system-load | GetLoadAverage | 返回数值型负载字段 |
| disk-info | GetDiskInfo | 返回有挂载点的磁盘数组 |

请求为 form-urlencoded；签名由 `request_time` 的秒级时间戳与 API Key 的双重 MD5 生成。详见 [官方认证说明](https://docs.bt.cn/api/)。密钥和 request_token 都不记录。客户端默认预览，只有 `--execute` 才发送一次请求。

其他操作按目标版本的官方模块文档准备参数。核对 action、方法、资源 ID、幂等性和响应含义，再按授权执行。写操作前查资源现状；HTTP 200 内的失败状态同样是失败。异步提交只记录为已受理，轮询或回读业务状态后才记成功。

以下错误的处理不同：

| 现象 | 先做什么 | 能否降级 |
| --- | --- | --- |
| 404 / action 不存在 / 参数或响应变化 | 判断是否错误 URL、登录页面或版本差异，启动文档核对与补丁验证 | 修复失败且确认未写入后评估 |
| 401/403、签名拒绝 | 核对时钟、权限、API 开关和 IP 白名单，不输出密钥 | 只能使用另行已授权的 SSH 身份，不能绕过权限 |
| TLS、DNS、网络超时 | 核对连接、信任链和网络；写操作先查是否已生效 | 只读可转路径；写入结果不明则停止 |
| 返回 200 HTML / 登录页 / 重定向 | 核对是否误用了面板安全入口或反向代理规则 | 禁止带签名追随重定向 |
| 业务错误 / 资源冲突 | 检查实际状态与参数 | 不把业务拒绝视作工具失效 |

不自动修改服务器白名单、关闭防火墙、关闭 TLS 校验或清除安全限制来“修复”连接。

## 路径 2：SSH 上的 btcli

官方 [btcli 文档](https://docs.bt.cn/getting-started/btcli-interactive-tool/) 介绍了交互资源管理。先通过已有 SSH 配置和密钥库使用主机别名，核对主机密钥。不要关闭主机密钥检查，不使用 `sshpass` 或在进程参数里放密码。

先探测命令存在：

```bash
ssh production-web 'command -v btcli'
```

只有确认目标、授权和 PTY 具备后，才在工具的持久交互会话中启动：

```bash
ssh -t production-web btcli
```

实际任务中替换主机别名；不要原样访问示例主机。使用当前菜单文字选择功能，逐项读取提示。创建/修改站点后回读站点配置并验证访问；删除菜单可能同时处理网站文件、数据库和 FTP，必须分别核对并确认关联影响。

没有文档或本机帮助依据时，不杜撰 `btcli site add ...`，不预先向 stdin 填一串菜单数字。需要 sudo 时沿用已批准权限；提权失败不是修改 sudoers 的授权。

若当前工具不能维护 SSH PTY 会话，说明限制并转交用户交互，或在确认等价能力后评估第三级。不借此自动安装、升级面板来获得 btcli。

## 路径 3：bt 与服务基础命令

官方 [bt 命令指南](https://docs.bt.cn/getting-started/bt-command-line-tool/) 用于面板管理。读取本机帮助与版本后选择对应操作。

| 场景 | 示例 | 条件 |
| --- | --- | --- |
| 面板状态 | `bt status` | 只读，退出结果还需结合服务状态 |
| 面板修复 | `bt 16` | 会拉取修复包并修改环境，展示方案后确认；不是只读检测 |
| 数据库 root 密码重置 | `bt 7` | 高危，必须确认，密码只安全输入 |
| 默认登录信息 | `bt 14` | 可能输出密码和安全入口，不进入普通终端采集/聊天日志 |
| Nginx 配置检查 | `/www/server/nginx/sbin/nginx -t` | 先确认本机实际路径，输出先检查敏感内容 |
| Nginx 重载 | `/etc/init.d/nginx reload` | 仅限已授权的配置变更，配置测试通过并保留回滚 |

命令路径、服务实现和菜单含义以本机与官方资料交叉核对；示例不是全局可靠映射。无法找到等价的站点/数据库操作就停止，不能对所有失败执行 `bt 16` 或重启服务器。

## 完成与失败报告

部署前核对项目构建命令、进程管理方式、运行用户、监听端口、站点根目录和反向代理；保留配置备份与回滚步骤。应用需要的凭证写入受限配置或密钥服务，不出现在站点 URL。

部署后验证进程/端口、配置语法、HTTP 响应、应用健康与必要的持久化状态。需要公开 URL 时仅输出业务地址。

完全失败报告：目标别名、已试路径、各路径失败类别、是否存在未确认副作用、已做/未做验证、已恢复状态、需要人工解决的具体阻断。不要为“凑齐三次”执行不相关或危险操作。
