# 工作流与记录职责

## 阶段选择

默认路径为：前置盘点 → 规划 → 实施与自检 → 复核 → 按需人工验收 → 结案回流。构建、打包与发布按任务需要接入。阶段是职责划分，不是固定审批链；已授权连续开发时推进至授权范围完成。只做方案、复核或流程文档时，以所请求的阶段为边界。

| 阶段 | 必要工作 | 出口 |
| --- | --- | --- |
| 前置 | 目标、授权、非目标、现行规范、已有改动、当前任务状态 | 范围清楚，未知项有处理方式 |
| 规划 | 真实入口与依赖、方案取舍、成功标准、变更与验证范围 | 可执行计划，或具体阻断决策 |
| 实施与自检 | 按依赖实现，执行适用验证，保留实际结果 | 目标范围已实现，有效证据及剩余边界明确 |
| 复核 | 核对范围、实际变更、证据身份与失败归因 | 当前交验结论；缺陷返回具体修复任务 |
| 人工验收（适用时） | 准备前置、操作清单与反馈方式 | 用户对指定版本和范围的明确确认 |
| 结案 | 回写稳定约定、确认依据、任务索引与延期事项 | 已完成范围和未完成事项可追溯 |

## 任务规模与记录

- 单点小改动：一份任务说明或交付回复即可，包含目标、实际变更、检查及未验证项。
- 多步骤或跨模块任务：保留一个现行计划、事实与进度记录，成功标准关联证据。
- 多轮修复或独立交接：补充复核任务、缺陷与结论；只有确需分工维护时才拆分文件。

已有工单、设计文档、ADR、测试报告或项目目录能承载信息时复用。目录、编号和文件名由目标项目决定。长期成功标准、关键执行结果与确认依据应进入持久记录，避免只存在于对话或临时日志。

| 记录 | 唯一职责 |
| --- | --- |
| 项目基线 | 当前目标、模块职责、关键契约与实际命令 |
| 事实记录 | 有依据的现状、假设、冲突及待核实项 |
| 实施计划 | 范围、授权、版本、依赖顺序、变更和验证矩阵 |
| 执行证据 | 实际动作、受测状态、结果及覆盖边界 |
| 复核任务 | 检查输入、准确步骤、通过标准和失败返回 |
| 当前结论 | 有效覆盖、缺口、归因及唯一交验结论 |
| 缺陷记录 | 复现、根因、修复、回归与关闭依据 |
| 验收与归档 | 待验收步骤、用户确认及已完成范围 |

可合并这些职责，但不在多处维护互相冲突的计划或当前结论。模板见 [任务记录](../assets/task-records.md)。

## 计划内容与变更

计划至少回答：完成什么、不做什么、改哪里、按什么顺序、怎样证明。按任务实际情况补充配置、数据、接口、资源生命周期、兼容或回退影响；不适用内容直接省略。

用可观察结果定义稳定 R 编号。多个标准可共享证据，一个标准也可有多项证据。新发现与目标冲突时记录冲突及依据，不以旧实现降低用户要求。

范围、路径、契约、技术方案或验证方法实质变化时递增版本，写明取代关系、受影响 R 和需要补验的项目。普通状态、排版和证据补录不制造新版本。用户变更需求时更新同一现行计划；明确另开任务才建立新范围。

## 按需复杂度评估

用于决定拆分与验证深度。机械小改动可一句话说明；多模块、关键状态变化、数据影响或未知可行性时，分别评估范围与边界、逻辑与状态、数据与契约、验证设计、不确定性，整体取最高等级。

| 等级 | 判断依据 |
| --- | --- |
| L1 微小 | 机械单点，输入、步骤和预期明确 |
| L2 常规 | 局部逻辑，边界清楚，有现成模式及可靠断言 |
| L3 中等 | 跨模块契约或多个状态，需要联动及异常验证 |
| L4 复杂 | 生命周期、并发、重试、恢复或一致性相互影响 |
| L5 高复杂 | 可行性或验证方法未知，应先探查并分阶段收敛 |

复杂度不等于风险、工作量或耗时，后三者单独说明。在计划形成、实质修订和开发完成时按需复评。不由等级推导额外审批、代理数量或执行工具。

## 接续与交接

恢复顺序：原目标及最新要求 → 当前授权和角色 → 现行计划及版本 → 工作区实际变更 → 有效证据 → 当前结论、未关闭项与下一动作。

状态询问先简短回答，再继续当前已授权工作。新消息默认补充当前目标；明确替换、暂停或停止时再调整。保留其他人已有工作，对共享索引做有界增量修改。

交接应让后续执行者无需猜测：任务与范围、资料路径、受测版本或变更身份、环境前置、准确步骤、预期、可复用证据、未验证部分、失败返回及允许修改范围。指令格式见 [提示词集](prompt-kit.md)。明确要求独立复核时，不将开发自检描述为独立复核。

## 人工验收与结案

验收项按真实依赖安排前置、基础能力、目标行为和回归。内部可复现缺陷先修复；外部环境、授权及人工体验作为明确人工项。

记录用户确认原话或可追溯位置、日期、受测版本与 R 范围。模糊反馈不当作通过，部分通过只覆盖对应范围。项目允许人工确认覆盖待执行复核时，分别记录人工依据与自动检查真实状态，不补造自动通过；已知失败和项目强制门禁按其规定处理。

结案按目标项目要求回流：

1. 更新现行基线中的稳定入口、契约和边界，不把执行日志复制成规范。
2. 必要时记录功能演进及不能回退的关键行为。
3. 归档已确认标准与证据，从现行待办中移出已完成项。
4. 更新任务索引，延期事项保留范围、原因和下一步。
5. 按明确政策处理过程记录。发布、数据处置和现场清理按各自授权执行。

无需人工验收的任务依据项目交付标准结案；确有未完成的实际工作时，保留当前状态和待办。
