# 成功标准、证据与交验判断

## 从需求到证据

用“触发与前置 → 可观察结果 → 失败表现”描述成功标准，不以“某层已修改”代替完成。需要追踪时为标准分配稳定 R 编号，验证执行结果分配 E 编号。

| 字段 | 要回答的问题 |
| --- | --- |
| 范围 | 哪个用户目标或原失败路径？ |
| 触发与前置 | 从哪个实际入口，使用什么输入、状态和配置？ |
| 可观察结果 | 返回、输出、状态变化或副作用应是什么？ |
| 关键内部边界 | 本次变化经过哪些模块、配置或调用环节？ |
| 验证设计 | 用什么入口和断言，隔离什么，哪些没有覆盖？ |
| 执行证据 | 哪项实际结果支持该结论，或仍待执行？ |

多个入口只有在行为或装配存在差异时分别覆盖。字段、配置或状态变化时，按实际链路检查输入、转换、使用、保存和后续读取；避免只验证定义存在。

缺陷先保留原失败输入、预期与实际结果。能复现旧状态时记录修复前失败；无法执行旧状态时如实说明。回归证据应能识别原失效场景，而不是只证明新代码存在。

## 证据最低内容

小任务简记即可；正式记录按以下字段保存：

- 关联 R 或检查项、实际时间、受测源码及适用配置、依赖和测试数据身份。
- 工作目录、真实命令或操作、各自退出码、具体断言及实际结果。
- 保留的内部边界、被替代的依赖、未覆盖环境和必要日志位置。

存在未提交变更时，提交号不足以标识受测状态，应补充差异、快照或等价标识。多个检查分别记录，不能只用最后一次成功遮盖前面的失败。列出待执行命令、进程启动中、检查数量或工具退出成功，都不单独证明用户目标成立。

## 真实边界与相称验证

至少对受本次变更影响的关键内部连接给出适用证据，例如实际调用方到处理方、配置装配到执行、写入到回读。外部系统可使用可控替代，但不能整体替代被修复的内部路径后宣称整条链路已验证。无需为了单点文档或机械改动构造不存在的业务链路。

验证层级如实标注：静态检查、单元、组件或模块集成、端到端、真实外部环境各自能证明的范围不同。命令成功还需核对预期输出或状态；截图适合视觉观察，不能独自证明数据流与副作用正确。

按变化选择异常输入、重试、并发、取消、超时、恢复或资源释放检查，不机械穷举所有场景。可逆低影响改动采用相称检查，避免只镜像实现的测试。项目要求的构建或必要生成检查属于验证；额外打包、部署或发布按当前目标安排。

环境缺失时说明缺失条件、可完成的替代检查和未验证边界，不使用历史产物冒充当前实现。不为取得真实证据擅自使用现役环境。

## 证据时效

源码、依赖、配置、测试数据或运行环境变化时，判断影响哪些结论，只补相关证据。无关文档改动或更换执行者不自动导致全量重跑。历史通过仅在受测条件仍匹配时复用；失效证据保留历史并标明替代项。

## 失败归因与修复

| 类型 | 依据 | 处理 |
| --- | --- | --- |
| 本轮新增或加重 | 开始基线、实际差异、具体诊断 | 交付前修复，不能因已有同类错就放行 |
| 已有且无关 | 明确位置、基线及关联分析 | 记录影响，不扩大清理范围 |
| 已有且阻断本次目标 | 能说明对目标路径的影响 | 作为本任务阻断处理 |
| 归因不明或环境缺失 | 未知点及缺失证据 | 补查或保持未验证 |

不得通过删断言、扩大排除、降低规则或改写成功标准制造通过。反复遇到同一阻断时调整诊断方法，检查根因及验证边界；确需外部条件或用户决策时提出有证据的具体缺口，同时继续独立可做部分。

修复记录包括复现、根因、原检查漏检原因、变更范围及新证据。“已改代码”和“有依据关闭”分别记录。

## 复核职责与当前结论

纯复核核对现行计划、实际变更、命名和引用、契约、证据身份、失败归因与验收前置，不修改实现或测试制造通过。用户明确要求复核并修复时，先保留失败结论，再实施修复与回归。

每个交接检查提供输入或环境、准确步骤、预期、已有证据或待执行部分及失败返回。没有适用自动检查时说明原因及替代证据，不造空命令。

| 当前交验结论 | 判定 |
| --- | --- |
| 不可交验收 | 目标未实现、必要检查失败、关键内部路径缺证据或失败归因不明 |
| 有条件可交验收 | 目标证据满足，仅有已界定的无关存量或范围偏差，且有明确接受依据 |
| 可交验收 | 所有适用目标与必要检查有有效证据，无本轮新增未解问题 |

偏差尚未接受时保持待决策，不用“有条件”掩盖阻断。每轮保留一个当前结论，历史结论标注取代关系。尚未完成必要复核时不提前放行。

分别记录实现、自动验证、交验资格、用户验收和结案。人工策略由 [独立配置](acceptance.md) 控制，缺省关闭，开启且非阻塞时不等待人工确认才结案；显式阻塞时只等待当前任务。自动通过不等于用户通过；人工确认也不改写自动检查历史。项目允许覆盖待执行复核时明确注明覆盖范围及依据，已知失败和强制门禁继续按项目规则处理。
