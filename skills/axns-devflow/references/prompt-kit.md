# 可复制的阶段提示词

按当前任务选择一条，替换已知的 `〈变量〉`。新项目采用 [最低目录结构](project-layout.md)，任务记录按规模创建；已有项目使用实际记录并建立目录映射。各条可独立使用，不要求重跑已完成阶段。普通小改动复用现有规范，可在交付回复中合并说明目标、变更、验证和未完成项，无需初始化流程或正式登记；已登记的扩展任务仍保留必要协议记录。若环境未安装本 skill，可在指令中补充可访问的 `axns-devflow/SKILL.md` 路径。

## 00 只整理项目流程与提示词

```text
使用 $axns-devflow，为〈项目或仓库路径〉整理项目开发流程与阶段提示词。本次只交付流程文档，输出到〈位置〉。
阅读适用的 AGENTS.md、现行规范、任务记录和实际目录，区分现行约定、有依据事实、历史背景与未知项。沿用项目技术选型和已有唯一记录入口，不从通用流程引入固定语言、框架、分层或业务源码目录。
新项目流程必须包含 references/project-layout.md 规定的完整 _doc、_plan 最低骨架、目录用途、README 导航和 _plan/flow.md；流程文件已授权落盘时执行node "〈技能目录〉/scripts/init-workflow.cjs" --project-root "〈项目路径〉" 或手工等价创建。仅要求单个输出文件时在该文件中包含结构与初始化方法，不另写范围外文件。
梳理盘点、规划、实施自检、复核、按需人工验收、结案和按需构建发布的阶段职责与出口，说明成功标准到证据的关系。小任务可合并记录，不建立空流程。
每个所需阶段提供一条可独立复制的完整提示词，各用一个 text 围栏代码块；替换已知输入。检查引用、状态和已有授权语义，交付已核实内容及待决策事项。
```

## 01 项目盘点与启动

```text
使用 $axns-devflow，处理〈仓库路径〉的项目启动。目标：〈目标〉；本次范围：〈仅盘点/已授权初始化〉。
先读项目规范及实际目录，记录未提交与未跟踪改动。已有项目复用选型、模块和命令；新项目只解决影响当前目标的必要选型，可查事实自行核实，真正阻断的产品决策明确列出。
梳理实际入口、依赖、配置、运行环境与检查命令，形成最小项目基线和可观察成功标准。不猜测版本、脚本或不存在的模块。
仅盘点时交付事实、目录差异及下一步，不执行初始化写入；已授权初始化时先用node "〈技能目录〉/scripts/init-workflow.cjs" --project-root "〈项目路径〉" 建立完整最低流程骨架，再按授权完成最小可运行链路并验证目标行为。核实并填写 _plan/prompts/project.md，从 _plan/prompts/stages.md 选择阶段指令，首个真实任务放到 _plan/process/。保留已有工作，报告实际命令、结果、未验证边界和当前阶段。
```

## 02 只做方案与实施计划

```text
使用 $axns-devflow，为〈任务标识〉制定方案与实施计划。需求及非目标：〈内容〉。本阶段交付方案，不改业务实现。
阅读现行规范、相关任务和真实入口，记录工作区基线。沿实际依赖追踪输入、处理、输出、状态及适用副作用，明确已有能力、事实源、契约和验证边界。
将用户可观察结果形成稳定 R 标准，给出方案取舍、准确变更范围、依赖顺序、风险及适用回退。核实检查命令或操作，建立 R 到验证方法的关系。
按规模简评复杂度；关键不确定性先设计有出口的探查。复用现有记录，保持唯一现行计划，不造空文档。
交付计划版本、事实与未知项，以及可进入实施或具体阻断结论。需要交接时提供完整 text 指令，不把方案完成写成实现或验收通过。
```

## 03 检查现有计划

```text
使用 $axns-devflow，检查〈任务标识〉的〈现行计划路径与版本〉。本次只检查计划，不改实现或测试，不为文档检查运行整套测试。
核对目标、非目标、成功标准与已有授权，检查真实入口、准确路径、依赖、受影响契约、执行顺序和验证设计是否足以实施。命令必须存在，未知条件要有核实方式。
按实际风险核对复杂度、回退和交接要求，不扩充无关工作。记录具体缺项与依据，结论给出计划检查通过或待完善。
已有执行授权继续有效；本次检查请求的出口是计划结论，需要后续交接时给出完整指令。
```

## 04 执行开发、自检与交接

```text
使用 $axns-devflow，完成〈任务标识〉：〈需求或计划路径〉。本次授权范围：〈开发交接/开发并复核/所需完整阶段〉。
恢复项目规范、目标、非目标、已有授权及唯一计划，记录实际工作区基线。计划不足时先补准确变更范围、依赖顺序与可观察 R 标准，再持续推进已授权工作。
按项目既有边界和实际依赖实施，复用公共能力。缺陷先保留失败输入、预期与实际结果，定位根因。实质变更更新计划及受影响验证，不覆盖无关工作。
执行相称检查，覆盖受本次变化影响的关键内部路径；替代依赖、缺失环境与未覆盖项明确标注。保存真实命令或操作、退出码、断言、受测身份及关联证据。修复本轮新增问题和阻断目标的旧问题。
复用仍有效的证据，按项目门禁决定必要构建；部署和发布按当前授权。完成本次所有已授权阶段，明确独立交接时保留边界。
交付实际变更、已做与未做验证、未关闭项、当前状态及必要接续提示词，不代替用户确认验收。
```

## 05 独立复核

```text
使用 $axns-devflow，复核〈任务标识〉，依据〈计划版本与复核任务路径〉。本次仅复核，可更新证据、结论与缺陷记录，不改实现、测试或成功标准以制造通过。
核对实际变更、受测源码及配置身份、R 标准、关键引用与契约、已有证据时效。先复用有效证据，再执行必要待做检查；没有适用自动检查时说明替代依据。
逐项保存真实步骤、环境、退出码、断言及隔离边界。按开始基线归因失败，内部可复现缺陷形成具体修复交接，不混入人工体验项。缺环境保持未验证。
给出覆盖、失败、未验证项及当前唯一交验结论；有条件项需具体影响与接受依据，未接受偏差保持待决策。用户已确认范围按项目规则处理并保留自动检查历史，不绕过强制门禁。
需要修复时提供失败输入、根因线索和可执行返回任务；需要人工验收时给出清单前置及完整交接指令。
```

## 06 修复复核问题

```text
使用 $axns-devflow，修复〈任务标识〉的〈失败记录或检查项〉。本次授权修复及受影响回归。
恢复现行计划、开始基线、实际差异、原失败输入及断言。定位根因与原检查漏检原因，不通过删样例、替代故障边界或降低标准制造通过。
只修改必要实现及受影响调用方。范围、契约、方案或验证方法实质变化时更新计划版本及后续检查；普通进度更新不另造版本。
补充能识别旧失效场景的证据，验证修复结果和适用回归，记录真实命令、退出码、受测身份与未覆盖边界。关闭项必须有验证依据。
交付修复点、根因、回归结果、未关闭项与下一动作。需要外部条件时列具体证据，继续不受阻的已授权工作。
```

## 07 生成人工验收清单

```text
使用 $axns-devflow，先读取独立人工验收配置，为〈任务标识〉整理按需的人工验收清单，依据现行计划、实现及最新交验结论，不代替用户勾选通过。
先核对已经明确通过的版本及范围并引用依据。未达到门槛的项标记准备中、待复核、内部修复或待决策，不把内部缺陷转给用户验收。
按实际依赖排列环境准备、基础能力、目标行为及回归。每项给出 R、受测版本、数据和环境前置、真实入口、编号操作、可观察预期、失败反馈及适用恢复方式。
如有总表和步骤，保持集合、顺序、状态与链接一致；已通过项归档并保留可追溯入口。交付待确认范围和反馈格式。
```

## 08 按策略归档与结案

```text
使用 $axns-devflow，处理〈任务标识〉的技术交付与结案。先读取 _plan/prompts/acceptance.json：缺省关闭人工验收；开启且非阻塞时单独跟踪，不等待确认才结案；只有显式 blocking 为 true 时等待本任务最终候选的确认。已有真实确认时记录依据、日期、受测版本和 R 范围；没有则如实标记未启用或待确认。
核实明确通过范围，模糊反馈不当作通过；部分通过分别保留未完成项。按项目规则判断确认是否覆盖待执行复核，自动检查真实历史不改写，已知失败与强制门禁按规定处理。
完成已授权且实际需要的结案事项：更新现行基线、必要演进、验收归档、任务索引及延期事项。无需的记录不创建，仍有实际工作时如实保留。
过程记录按项目政策处理；结案不扩张发布、数据处置或清理授权。报告技术结案范围、独立人工验收状态、依据入口及剩余事项；非阻塞人工待办保留在台账。
```

## 09 按需构建与发布

```text
使用 $axns-devflow，完成〈任务标识〉的〈构建或交付目标〉。产物位置：〈路径〉；当前授权：〈仅生成产物/具体部署或分发目标〉。
读取项目实际脚本，核对受测源码及未提交变化、依赖、配置、版本事实源与适用质量门禁。依据当前交付形态执行必要构建，记录真实命令、退出码及产物身份，不以历史产物或预演冒充本次结果。
验证与交付形态相符的实际行为，说明未执行或环境缺失项。完成已授权范围；需要额外发布授权时先准备可审查产物和具体发布内容。
交付准确产物路径、来源、版本、验证结果与实际分发状态。构建成功、用户验收和公开发布分别记录。
```

## 10 接续任务与恢复状态

```text
使用 $axns-devflow，继续〈任务标识〉。恢复原目标、最新要求、授权阶段、现行计划及版本、实际工作区、有效证据、最新结论、未关闭项和待确认范围。
先简短说明实现、验证、交验、用户验收与结案状态，再处理当前下一步。仅复用受测条件仍匹配的证据，未验证不继承为通过，不重建有效方案或重复请求同一授权。
本次角色以用户分配为准，要求连续推进时完成已授权阶段，要求独立交接时保留边界。新消息默认补充当前任务，明确变更目标或停止时再调整。
记录新增结果及待办，交付当前状态和必要的完整接续指令，保持回复与持久记录一致。
```
