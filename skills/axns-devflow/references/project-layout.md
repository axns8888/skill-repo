# 新项目最低目录结构与快速初始化

本技能供个人跨项目复用。新项目的流程至少包含下列目录和入口；可增加项目专属内容。目录骨架与任务记录的规模分别处理：骨架完整建立，具体任务只创建有实际用途的记录。

```text
<项目根目录>/
├─ _doc/
│  ├─ demos/                    # 示例、样例输入与复现材料
│  ├─ scripts/                  # 资料、演示、诊断与维护辅助脚本
│  ├─ 使用说明文档/              # 安装、配置、操作、排障与维护说明
│  ├─ 第三方插件文档/            # 外部插件、SDK或服务的接入资料
│  └─ README.md                 # 项目资料导航
└─ _plan/
   ├─ future/                   # 延期及尚未进入本轮实施的事项
   ├─ guides/                   # 跨任务阶段指南、质量门禁及记录模板
   ├─ ledger/                   # 任务台账、结案摘要与验收归档索引
   ├─ process/                  # 进行中任务的计划、证据、复核与待验收项
   ├─ prompts/                  # 当前项目开发约定与可复制阶段提示词
   ├─ flow.md                   # 阶段总览、阶段出口和下一步
   └─ README.md                 # 开发流程总入口
```

每个子目录附带有用途和维护边界的 README.md，保证空内容阶段也能随 Git 保留。最低结构不限定业务源码、测试、构建工具或发布目录；沿用项目技术栈的组织方式。

## 一次初始化

有 Node.js 时，在任意工作目录执行；替换技能目录和目标项目路径。不需要安装第三方包，Node.js 只用于运行此辅助工具，不决定项目技术选型。

```powershell
node "<技能目录>/scripts/init-workflow.cjs" --project-root "<项目路径>" --project-name "<项目名称>"
```

- --project-root 必填，可指向尚不存在的目录；省略 --project-name 时使用项目目录名。
- 加 --dry-run 只列出将创建和将保留的文件，不创建目标目录。
- 重复执行只补缺失项，已有文件逐字保留；不会自动合并或升级旧版规范。
- 目录/文件类型冲突会在写入前报错；目标结构内的符号链接不作为写入位置。
- 只初始化开发流程，不安装依赖、不生成业务工程、不运行构建、不修改目标项目的 AGENTS.md。

没有 Node.js 或本次要求手工生成时，按技能目录下 assets/workflow/ 的骨架直接创建同等结构，并使用技能自带基线、阶段提示词、工作流、质量门禁及任务记录模板填充对应入口。

## 自动落位与开始开发

| 项目文件 | 初始化内容与后续维护 |
| --- | --- |
| _doc/README.md、各子目录 README.md | 资料导航、用途和维护边界 |
| _plan/README.md、flow.md、各子目录 README.md | 流程导航、阶段顺序、索引及目录分工 |
| _plan/prompts/project.md | 当前技能的项目基线模板；只替换项目名称，其余待据实填写 |
| _plan/prompts/window/P0-open.md 至 P5-escalate.md | 共用窗口提示词；P5 仅 worktree 扩展启用时使用 |
| _plan/prompts/stages.md | 当前技能的完整阶段提示词，保留对应技能调用名 |
| _plan/guides/workflow.md、quality-gates.md、project-layout.md | 当前技能的工作流、证据门禁与目录约定 |
| _plan/guides/task-records.md | 任务记录模板；按需抽取到 process/ |

初始化后先核实并填写项目基线，再选择阶段提示词开始本次任务。模板中的未知项保留待核实，不编造命令、版本、实现和通过状态。prompts/ 中维护现行约定及可复制指令，process/ 中维护执行事实，ledger/ 中索引已完成结果；延期项转入 future/，面向使用者的资料进入 _doc/。

## 生成流程与接续规则

1. 为新项目生成流程时，明确包含完整最低结构、目录用途、初始化方式、流程入口和阶段提示词。授权写入流程文档时，实际创建这些目录和入口；仅要求回复方案或指定单个输出文件时，在该交付中包含结构及创建方法，不另写范围外文件。
2. 已授权初始化时可直接执行脚本，再按已知事实填写基线和首个真实任务；仅盘点不执行写入。未知业务选型不妨碍先建立已授权的文档骨架。
3. 已有项目先检查当前规范、目录及未提交工作，复用唯一事实源；用户要求补齐结构时增量补缺，等价载体在 README.md 中建立明确映射，不重建第二套计划。脚本跳过文件后仍须检查引用和内容兼容，必要时有界增量整合。
4. 骨架是最低约定，任务过程文件按规模裁剪。不要把“不造空任务记录”理解为可以省略骨架，也不要为了填满骨架预造空架构、迁移、验收、演进或业务模块文件。
5. 阶段指南、当前基线、任务记录和归档分别维护；结案回写稳定约定与索引，过程记录按项目政策保留，不默认删除。

## 可选窗口与 worktree 目录

初始化始终复制 `prompts/window/P0–P5`，默认仍为单任务，不创建任何运行中的任务、指针、注册表或 worktree。正式单任务登记使用 `_plan/.active_plan`，计划与证据放 `_plan/process/<task-id>/`。

启用独立的 axns-devflow-ext-worktree 后，按该扩展在主检出目录增加 `.worktrees/`、`_plan/active/`、`_plan/archive/` 和 `_plan/registry.jsonl`。这些是本地共享运行状态，按扩展要求忽略；不能把每个 worktree 中的目录副本当成共享状态。任务记录仍属于原来的 process 职责，合入后保留。不开扩展不创建这些目录。
