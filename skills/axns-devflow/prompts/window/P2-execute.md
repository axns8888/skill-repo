# P2 阶段 1：执行

执行 axns-devflow 阶段 1。当前 task-id：{{task-id}}。先回报工作目录、范围、依赖状态及计划，再推进已授权步骤。

1. 在任务 worktree（单任务模式为当前项目目录）推进计划，将真实命令、测试、diff 和当前结论写入 `_plan/process/<task-id>/`。
2. **若 worktree 扩展启用**，开始执行、每次提交前运行扩展 check：路径与分支正确；已提交差异、暂存、未暂存及未跟踪文件均在 scope 或已持有的 shared_claims 内；依赖已完成；登记未被暂停；元数据与共享指针一致。不满足则阻断提交。
3. 已授权的 worktree 任务默认自动提交本任务范围内的变更，可用扩展 commit 校验、暂存并加 `<task-id>:` 前缀；无需逐次再问。用户要求仅评审或保留未提交状态时遵从。没有提交时哈希写“未提交”。
4. 需要扩大 scope、增加 shared_claims 或改变依赖时，先核实是否仍为完成已授权目标所必需。已有授权覆盖且影响可控时记录原因、影响任务与依据，用 claim --manifest --reason 重新仲裁；涉及新目标或重大方案取舍时才请求用户决定。不能先改后补持权。
5. 每完成可验证步骤即回报做了什么、证据位置与命令摘要、实际哈希、自检结论、剩余项。
