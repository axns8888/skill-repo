# P4 阶段 3：验收与合入

执行 axns-devflow 阶段 3。当前 task-id：{{task-id}}。先回报阻断项关闭情况、验收检查、候选提交及现有合入授权；不满足前置条件则停止合入。

**若 worktree 扩展启用**：

1. 读取共享登记，按 depends_on 拓扑顺序处理；依赖未 completed 不合入。共享文件任务依次持权、验收、合入、释放。
2. 在干净的**任务 worktree** 中读取最新本地集成分支提交，执行 `git merge --no-ff --no-commit <集成分支>`，避免快进绕过检查。有冲突返回阶段 1，所有冲突都在任务分支解决。
3. 对组合结果做接口/夹具/锁文件语义检查及验收命令，记录实际结果。通过后在已有提交授权内完成带 task-id 前缀的合并提交；已是最新时不造空提交。记录准确 HEAD 与被验证的代码/树身份；后续代码变更使验收失效。
4. 在任务目录维护 `acceptance.md`：阻断项关闭证据、命令及结果、语义复核、验收人与确认依据。提交该记录，确认最终候选；文档提交若影响门禁，重跑相应检查。未获用户验收则保持待验收，不合入。
5. 具备合入授权后，在干净的集成工作区核对集成分支未前移，执行 `git merge --ff-only task/<task-id>`，使其指向已验收候选。快进失败则返回任务 worktree 重新组合验证，不在集成分支解决冲突。
6. 从主检出目录执行扩展 finish，传入真实已验收 HEAD；它检查干净状态、已合入和证据文件后清理 worktree、归档指针、追加 `task.completed` 并释放修改权。清理失败时保留活动记录与持权，报告原因。任务分支保留至迭代结束，删除另按项目授权执行。

**若扩展未启用**：按宿主验收出口及已有授权完成交接/合入，更新 `_plan/.active_plan`，不创建扩展登记文件。

回报：合并验证与冲突文件、语义及验收结果、实际候选/集成提交、顺序与依据、持权释放记录、归档路径、清理结果、最终状态。未执行部分明确写未执行。结案后关闭窗口，新任务另开窗口从 P0 开始。
