# 任务记录模板

按阶段和规模选用，可合并到现有工单或文档。`〈变量〉` 据实填写，未执行写未执行；不适用章节直接省略。R 是成功标准，E 是执行证据，C 是复核检查，F 是缺陷，可映射到项目已有编号。

新项目默认将真实任务记录放到 `_plan/process/`，默认使用 `<task-id>/` 归集同一任务的计划、证据和结论；普通小任务可用单文件或交付回复，不必逐项填写本模板；需要跨会话接续时再持久化必要事实。窗口协议固定使用 `_plan/process/<task-id>/`。当前项目约定维护在 `_plan/prompts/`，结案摘要及验收归档索引进入 `_plan/ledger/`，延期事项进入 `_plan/future/`；不缩减最低目录骨架。

## 任务卡与事实

原生任务清单组织当前步骤即可；以下平台关联仅在跨工具或自动化执行需要时填写，无需另建同步台账。

- 原生清单关联：〈在步骤文本保留 task-id / 当前阶段 / 适用 R 编号〉
- 工作目录与交接依据：〈实际目录；启用 runner 时使用原工单 owner / dispatch_id，不当作平台 session-id〉
