# {{project_name}} 开发流程

默认使用 ${{skill_name}}。这些阶段用于划分职责；连续开发按已有授权推进，独立交接按用户要求执行。

| 阶段 | 必要动作与出口 | 记录入口 |
| --- | --- | --- |
| 项目启动 | 核实目标、现有工作、工具与实际命令；填好当前基线中的已知事实 | [项目基线](prompts/project.md) |
| 规划 | 定义可观察成功标准、准确变更范围、依赖顺序和验证方法 | [任务记录](process/README.md) |
| 实施与自检 | 完成授权范围，记录真实命令、断言、结果和未覆盖边界 | [任务记录](process/README.md) |
| 复核 | 关联成功标准与有效证据，给出当前结论；缺陷返回修复 | [质量门禁](guides/quality-gates.md) |
| 人工验收（独立可选） | 读取 [独立配置](../../../references/acceptance.md)，默认关闭；非阻塞时单独跟踪；启用后记录真实确认的版本、日期和范围 | [任务记录](process/README.md) |
| 结案 | 回写稳定基线、已确认范围、任务台账及延期事项 | [台账](ledger/README.md)、[延期事项](future/README.md) |
| 构建与发布（按需） | 按实际交付目标和授权执行，记录产物身份与真实分发状态 | [阶段提示词](prompts/stages.md) |

第一次使用：按 [工程要求](../../../references/engineering-standards.md) 填写项目基线、架构/源码树、命名/注释和适用 UI 规范 → 从阶段提示词选择本次指令 → 创建一个任务记录并开始。模板未知项保留待核实，不将模板、目录已创建或命令退出成功视为任务通过。

完整阶段职责见 [工作流](guides/workflow.md)，可复制指令见 [阶段提示词](prompts/stages.md)。

窗口任务从 [P0 开窗](../../../prompts/window/P0-open.md) 进入，阶段 0–3 对应 P1–P4；P5 仅扩展启用时协调升级。P0 核实并回报后沿用已有授权，只有明确要求回报后确认或缺少必要决定时才等待。已有任务从当前阶段接续；普通小改动可在现有记录或交付回复中合并说明变更与验证，不要求正式登记。扩展只由 AGENTS.md 的 extensions 启用，正式登记任务归集在 `_plan/process/<task-id>/`。
