# 文案风格与案例对齐

## 案例对齐原则

用户常粘贴「其他项目已成功提交」的字段作为格式样板。处理方式：

| 类别 | 做法 |
| --- | --- |
| 开发硬件（具体 CPU/内存/硬盘） | 可直接沿用用户本机/案例机型写法 |
| OS / 运行平台 / Chrome 内核浏览器 | 可沿用简短案例格式 |
| 开发工具、支撑软件中的版本与产品名 | **必须改为本仓库真实栈**（勿照抄 IDEA、MySQL 5.7、Java 17 等） |
| 开发目的 / 领域 / 主要功能 / 技术特点 | **整段按本项目重写**；只学叙事密度与结构，不搬业务 |

案例笔误（如「128G以上内存」实为硬盘）在本项目产出中写正确表述。

## 环境类推荐短句（可改）

```
开发的硬件环境：Intel(R) Core(TM) i9-11900H CPU，内存 32G，硬盘2T
运行的硬件环境（Web）：PC 端，2G 以上运行内存，128G以上硬盘
运行的硬件环境（H5）：移动端，2G以上运行内存，32G以上存储
开发操作系统：WINDOWS 11
运行平台：WINDOWS、Linux
支撑环境：基于Chrome内核的浏览器
```

## 主要功能结构（500～1300）

1. **开篇**：本软件是一款基于〈架构〉的〈产品类型〉，采用〈后端〉构建服务，前端使用〈前端栈〉，数据库采用〈DB/缓存〉。  
2. **定位**：面向〈用户〉，实现〈闭环能力〉。  
3. **模块清单**：软件的核心功能模块包括……  
4. **分述**：按模块 2～4 句说明「能做什么」，不写操作步骤级细节（那是操作手册）。  
5. **收束**：一句总结访问方式或业务价值。

语气：书面、客观、可核验；避免「独创/革命性」等无法证明的夸大（除非用户明确要求）。

## 技术特点（≤100）

优先顺序：架构形态 → 前后端技术点名 → 鉴权/权限 → 数据层 → 1～2 个业务特色。  
禁止把无关 buzzword（物联网、AI 预测性维护等）塞进非该域项目。

## 编程语言拼接

按实际出现的语言拼接，常见：

- Web + Python：`HTMLJavaScriptPythonSQL`
- Web + Java：`HTMLJavaScriptJavaSQL`
- 含明显 CSS 独立交付时：可加 `CSS` → `HTMLCSSJavaScriptPythonSQL`

TypeScript 项目通常仍写 `JavaScript`（登记表惯例），除非用户要求写 `TypeScript`。

## 多端命名

| 错误 | 正确 |
| --- | --- |
| 一份 MD 混写管理端+员工端功能 | 各一份，项目名称不同 |
| 员工端主要功能写「岗位编制维护」等管理端能力 | 只写员工自助已实现能力 |
