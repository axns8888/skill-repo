# 软著操作手册撰写规则（通用强制）

复制到项目 `_doc/软著申请/rule/project_rule.md` 时，把「〈项目名称〉」换成真实名称；多端则分文件或分节写清各端全称。

## 1. 命名与边界

1. 手册全文统一使用申请项目名称：**〈项目名称〉**。  
2. 同一份手册只描述一个端（如仅管理端 Web，或仅移动端 H5）。  
3. 可客观提及配套后端，但不另冒充第三套「界面操作说明书」除非单独申请。  
4. 多套软著 → 多份手册，名称与截图目录隔离。

## 2. 文体与结构

1. 客观严谨；用「用户」「操作人员」「系统」，避免口语与营销话术。  
2. 必备：引言、运行环境、功能概述、详细操作步骤；建议：登录专章、常见问题、附录。  
3. 详细步骤编号清晰；配合图号（「如图 n 所示」或先行 `【图n　标题】`）。  
4. 汉字数不足时扩充：前置条件、字段含义、结果校验、失败提示——禁止无意义堆砌。

## 3. 内容真实性

1. 以仓库**已实现**功能为准，禁止写规划中未上线按钮/流程。  
2. 账号、端口、地址以 README / 环境配置为准。  
3. 状态枚举、字典标签与界面一致。  

## 4. 截图规范

1. 目录：`Screenshot-web/`、`Screenshot-h5/`（或按端命名）。  
2. 文件名：`图01-登录.png`（两位序号 + 中文简述）。  
3. 清晰可读；注意脱敏；图号与正文一致。  

## 5. Word 排版

1. 封面 + 目录占位 + 正文；目录区只写「替换目录」（不自动生成条目）；页眉项目名称与版本；页脚页码。  
2. 第 4 章直接写「系统架构」；原「功能模块」一览表下沉到第 5 章各功能小节开头，不集中罗列。  
3. 凡 Markdown 标题（`#`～`#####`）均须带序号（如 `5.1.1.1`；附录可用 `附录 A` / `A.1`）。「操作步骤」「注意事项」为**加粗普通正文**（非标题），不占标题序号；标题下或加粗段落下的列表从 1 重计。  
4. 「1.2 适用范围」只列一级模块名称，不重复展开子功能。  
5. 图下：「图 n　标题」。  
6. 定稿删除 TODO、未替换的占位说明（已嵌图时）。
