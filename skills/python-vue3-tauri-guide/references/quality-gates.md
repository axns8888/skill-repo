# 成功标准、验证证据与放行

## 需求到证据

独立成功标准分配稳定 R 编号，用用户触发和可观察结果描述，不以“前端/后端已改”代替完成标准。

| 字段 | 内容 |
| --- | --- |
| R编号与范围 | 本次实际需求或失败路径 |
| 触发与前置 | 从哪个真实入口操作，使用什么数据/配置 |
| 可观察结果 | 页面、返回、回读及关键副作用，包含失败表现 |
| 调用链 | 配置/编辑/保存/校验/装配/执行/回存/后续读取中适用部分 |
| 验证边界 | 测试入口、业务断言、被替换外部依赖、不适用项及原因 |
| E编号 | 已执行证据，计划期允许标待执行 |

有多个入口时覆盖真实入口差异，例如新增/编辑、试跑/正式、恢复/重试。字段变更核对注册、类型、编译、运行装配、保存往返和下游使用；`0/false` 被默认值吞掉、对象被错误解包、实例身份混淆等按实际风险验证。

缺陷先保留失败输入与预期断言，能复现时记录修复前失败。无法执行旧状态时说明原因，不编造先失败后成功。针对根因补能拦截旧失效场景的证据，不删失败样例或只增加“认真检查”。

## E证据最低内容

- E编号、关联R/检查ID、实际执行时间、受测源码/配置/依赖/夹具身份。
- 工作目录、真实命令或操作、退出码、具体断言/回读/副作用次数。
- 保留的真实内部边界、被替换依赖与未覆盖部分；必要日志位置。

dirty 工作区不能只引用 HEAD；记录任务开始基线与当轮 diff/快照。多个命令分别保留结果，不用最后一条成功盖过前面失败。启动未完成、仅列计划命令、只看测试总数均不构成通过。

## 真实边界

- 单函数探针、组件事件、真实HTTP、临时数据库、原生Tauri和真实第三方分别标注，不互相冒充。
- 至少一个适用检查跨越本次最易断裂的内部接线；外部网络、时钟、厂商可隔离，被修复的内部装配/保存链路不能整体mock。
- 请求200不证明成功，要断言业务字段、数据库或状态回读及关键副作用次数。
- UI事件必须证明连接到参数、状态和可见结果；Tauri插件必须有原生环境证据或明确待验证边界。
- 真实外部环境缺失时可用可控适配替身，但须声明未验证真实服务；不为“真实链路”擅自调用生产账号、库或他人窗口。
- 截图只提供视觉观察，不能替代DOM交互、请求次数、事务和回读证据；遵守目标项目授权。

## 证据时效与检查范围

源码、依赖、配置或夹具变化后判断哪些证据失效，只补相应项。无关文档改动不使全部代码证据失效，更换执行者也不要求机械全量重跑。

按风险选择重试副作用、并发竞争、取消、超时、恢复、隔离与资源释放场景。可逆文案/简单样式用相称检查，不为了测试数量写镜像实现。日常不自动跑生产构建和全仓lint；遇新改动、失败或未解决疑点再扩大检查。

## 失败归因

| 类型 | 必要依据 | 处理 |
| --- | --- | --- |
| 本轮新增/加重 | 开始快照、实际diff、同规则具体诊断 | 交付前修复，不能因同文件已有同类错就放行新增 |
| 已有且无关 | 明确位置、基线和关联分析 | 记录影响，不顺带扩大清理 |
| 已有但阻断目标 | 证明如何影响本次路径 | 视为本任务内部阻断 |
| 归因不明/环境缺失 | 未知点与缺失证据 | 补查或保持未验证，不能写成存量/通过 |

不得通过降低规则、扩大排除、删断言或伪造结果过门禁。反复同一阻断时更换诊断方法，检查根因和测试边界；只有需要外部条件或用户决策时带证据提出具体问题，不以重试次数作为结束配额。

## 自动复核职责

按32定义核对范围、命名/引用、契约、证据身份、失败归因与验收前置。复核仅维护证据和结论；纯复核请求中不修改业务、迁移或测试逻辑以制造通过。需核心修复时记录41并交回开发；用户已要求复核及修复时分别记录阶段并完成授权修复。

每个复核项具备检查ID、R、输入/环境、准确命令或操作、预期、已有证据/待执行部分、失败返回条件。没有适用自动检查时说明原因和替代证据，不造空命令。

## 当前唯一结论

| 结论 | 判定 |
| --- | --- |
| 不可交验收 | 成功标准未实现、必要检查失败、内部接线无证据、证据失效或失败归因不明 |
| 有条件可交验收 | 目标证据满足，仅剩有基线的无关存量或明确范围偏差；列具体影响及用户接受依据，未接受的偏差仍待决策 |
| 可交验收 | 所有适用目标和必要检查有有效证据，无本轮新增未解问题 |

内部保存、参数、装配、事务和回存错误必须内部修复，不改名为“待人工”。真实授权、外部服务环境和人工视觉体验可保留为明确人工项。待复核时交验尚未放行；报告中保留一个当前结论，历史轮次注明取代关系。

分别记录：实现、自动验证、交验资格、用户验收、结案。自动通过不等于用户通过。用户明确通过可覆盖对应范围待执行的自动复核，但只记录人工依据及“已被覆盖”，保留未执行/失败历史，不伪造自动通过；未覆盖和后续变更继续原流程。
