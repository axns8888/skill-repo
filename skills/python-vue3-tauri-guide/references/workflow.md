# 开发工作流与文档职责

## 适用方式

本流程提炼自 TK-Worker 的 00～04 指南。保留决策、证据与交接机制，路径可映射到目标项目；无需复制来源项目的业务内容。已有任务系统、ADR 或测试报告能承载相同信息时直接复用。

阶段为：前置 → 规划 → 实施与自检 → 自动复核 → 人工验收 → 结案回流。构建发布按需接入，人工验收与发行冻结分别判断。用户已要求连续实施时推进所有已授权阶段；明确独立交接的阶段由用户指定执行者，不自动派生代理。

## 文档组织范例

```text
_plan/
  README.md                       # 导航、阶段与目录边界
  guides/                         # 跨任务流程，唯一维护通用规则
  prompts/                        # 项目与领域当前开发基线
    project.md                    # 示例名；现有项目沿用现行文件名
    ui.md
    module_<domain>.md
    evolution/                    # 按模块/功能记录转折
      acceptance/                 # 已确认验收的标准和依据
  process/
    README.md                     # 任务索引
    tasks/<task-id>/               # 进行中的正式计划与证据
    90_finish_check.md             # 当前待验收总表
    91_finish_check_step.md        # 可执行步骤
  ledger/tasks.md                 # 结案薄索引
  future/                         # 明确延期范围
_doc/                             # 使用、排障、维护、外部接口资料
.planning/                        # 可忽略的本机探针、日志、截图和草稿
```

长期成功标准、关键命令及结果摘要须进入正式记录，不能只留在临时目录或对话中。只有必要时新建这些文件；纯文档或小改动可合并到一份任务记录。不要为格式齐全制造空架构、空迁移或空验收项。

## 阶段与出口

| 阶段 | 必要工作 | 记录与出口 |
| --- | --- | --- |
| 00 前置 | 用户要求、授权、非目标、工作区 dirty/untracked、现行入口和任务绑定 | 事实与范围明确；未确定项有后续处理方式 |
| 01 规划 | 真实调用链、唯一事实源、边界、复用点、状态与生命周期、R 标准 | 架构和方案可实施，或具体待决策项 |
| 02 实施 | 唯一实施计划、版本、复杂度、文件/接口变更、验证矩阵；实现与自检 | 完整实现、有效证据、准确复核任务与交接 |
| 03 自动复核 | 按交接检查范围执行，复用有效证据，归因失败 | 交验结论；核心缺陷交回开发 |
| 04 人工验收 | 前置部署/数据准备、可操作步骤、真实环境和体验确认 | 用户明确通过/部分通过/不通过 |
| 结案 | 回写当前基线、演进、验收档案、任务索引；有迁移时处理实际合并 | 已确认范围有可追溯终态，未完成项保留 |

## 任务记录范例

| 文件 | 唯一职责 |
| --- | --- |
| `01_project_framework.md` | 架构、数据流、真实入口、所有权和生命周期 |
| `02_project_plan.md` | 方案、阶段依赖和任务卡；小任务可并入 20 |
| `10_findings.md` | 有证据事实、假设、冲突、待查项 |
| `20_plan.md` | 唯一实施计划、授权依据、计划版本、R 矩阵和准确变更范围 |
| `22_plan_complexity.md` | 各计划版本的复杂度及开发完成复评 |
| `30_progress.md` | 实际执行、命令、退出码、E 证据及计划检查结果 |
| `32_auto_review_task.md` | 后续复核任务定义、输入、步骤、断言和交接 |
| `40_verify.md` | 证据判定、缺口和当前唯一交验结论 |
| `41_fix.md` | 失败复现、根因、漏检原因、修复与关闭依据 |

不在多个文件维护互相冲突的实施计划或当前结论。文件命名是可复用约定，目标仓库已有命名时建立等价映射。

## 复杂度评估

按范围与边界、逻辑与状态、数据与契约、验证设计、不确定性五维分别评估，整体取最高级，风险、工作量与耗时另列。

| 等级 | 判断依据 |
| --- | --- |
| L1 微小 | 机械单点，输入、步骤、预期齐全 |
| L2 常规 | 局部逻辑，边界清楚，已有模式和可靠断言 |
| L3 中等 | 跨层契约或多个状态，需要设计联调和异常验证 |
| L4 复杂 | 多模块生命周期、并发、重试、取消、恢复或迁移一致性联动 |
| L5 高复杂 | 可行性或验证方法未知，需要先实验并分阶段收敛 |

计划形成、范围/路径/契约/验证方法实质修订、开发完成时记录评估；保留计划版本和取代关系。小任务简写即可，等级不触发额外审批，也不用于自动选择执行者或型号。

## 接续与变更

先恢复当前计划、实际 diff、证据时效、最新结论和未关闭项。状态询问先简短回答，再继续当前已分配工作。新消息默认补充当前任务，明确更换目标才另开范围。

实质变更递增计划版本，只补受影响证据；普通结果或排版更新不制造新版本。多个任务共享索引时做有界增量编辑，不用旧整文件覆盖他人内容。

## 人工通过与结案回流

记录确认原话、日期、受测版本及具体 R 范围。明确人工通过的范围可直接进入归档，自动复核标“已被人工验收覆盖”，不补造空报告或自动通过；未确认部分继续原流程。验收后新增行为按新范围重新判断。

回流内容：

1. 当前项目/领域基线：只写已经成立的边界、契约、入口和未闭环项。
2. 模块演进按二级功能维护“当初、转折、现行、勿回退”，不堆日期化全文或工具日志。
3. 已通过的标准与确认依据进验收归档，现行 90/91 只留待办，并同步任务集合、顺序、前置、状态和链接。
4. ledger 记录任务号、影响范围、确认与归档入口；延期内容进 future。
5. 迁移验收合并、过程目录归档/删除遵守目标仓库政策；没有明确规定时保留可追溯记录，不机械删除。

未获用户确认时，只能描述开发完成、复核通过或待验收，不得替用户勾选通过。
