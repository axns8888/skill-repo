# 可直接复制的开发流程提示词

首次使用、最简调用与跨项目分享见 [使用说明](../README.md)。

选择本次阶段；把已知的 `〈变量〉` 替换为真实值。新项目采用 [最低目录结构](project-layout.md)；已有项目先核实等价载体并建立映射，具体任务记录按规模创建。各条可独立复制，不要求按编号重新跑已完成阶段。实际调用应使当前工具能够读取本 skill 及目标仓库。

## 00 只整理项目专属流程与提示词

用于需要开发规范/提示词交付，尚未要求修改业务的场景。

```text
使用 $python-vue3-tauri-guide，为〈项目名称/仓库路径〉整理 Python + Vue 3 + Tauri 的项目开发流程与阶段提示词。本次只交付流程文档，不启动业务开发或构建。
阅读项目 AGENTS.md、现行 _plan/_doc 或等价规范、依赖清单和实际目录，区分现行契约、历史背景、当前事实与待决策项。沿用现有框架和目录；新项目未知部分明确列出可配置项，不编造版本、脚本或接口。
新项目流程必须包含 references/project-layout.md 规定的完整 _doc、_plan 最低骨架、目录用途、README 导航和 _plan/flow.md；已授权写入流程时执行node "〈技能目录〉/scripts/init-workflow.cjs" --project-root "〈项目路径〉" 或手工等价创建。仅要求单个输出文件时在该文件中包含结构与初始化方法，不另写范围外文件。
整理前置、规划、实施交接、自动复核、人工验收、结案和按需发布的工作流，明确三端职责、配置事实源、Sidecar生命周期、数据迁移、组件/样式所有权、R需求到E证据及阶段状态。
所有批量写操作固定为前端一次提交服务端，写明输入校验、事务或部分成功、审计、任务化及一次请求和真实后端隔离库的验证要求。
每个阶段给一条可独立复制的完整提示词，每条单独使用text围栏代码块。必要模板与来源说明分开维护；不要把项目专属端口、组件、历史授权、凭据或兼容政策推广为通用规则。
交付到〈输出位置〉，检查引用、编码、阶段出口和已有授权语义，说明已核实内容及尚待填写项。
```

## 01 项目盘点与初始化

```text
使用 $python-vue3-tauri-guide，处理〈仓库路径〉的项目启动。产品目标：〈目标〉；交付模式：〈仅盘点 / 已授权初始化〉；目标平台：〈平台与架构〉。
先读 AGENTS.md、现行基线与实际目录，记录已有未提交改动。已有项目复用框架、组件和工具链，不重新搭建平行项目。新项目先确认 Python 服务框架、Vue工具链、Tauri版本与本机能力、数据库、通信方式和安装/便携形态；可查事实直接核实，只对真正影响产品边界的未知项提出具体决策。
明确 Python业务与持久化、Vue交互、Tauri桌面与Sidecar生命周期，梳理配置事实源、数据目录、依赖锁文件和开发/测试/打包入口。端口、版本、路径与命令不得凭来源示例猜测。
仅盘点时交付项目基线、目录差异与下一步，不执行初始化写入；已授权初始化时先用node "〈技能目录〉/scripts/init-workflow.cjs" --project-root "〈项目路径〉" 建立完整最低流程骨架，核实并填写 _plan/prompts/project.md，真实任务落到 _plan/process/，再补齐当前目标所需的最小可启动链路和锁定依赖，证明健康检查、前端到真实服务调用和本次需要的桌面启动行为。缺失环境如实记录，不用Mock业务或旧产物冒充。
完整保留最低目录骨架，具体任务只建立有实际用途的正式记录与R/E矩阵，保留当前工作，报告已完成范围、真实命令与结果、未验证边界及当前阶段。
```

## 02 只做架构与方案

```text
使用 $python-vue3-tauri-guide，为任务〈任务号〉制定架构与方案。需求：〈目标、成功标准、非目标〉。本阶段不改业务代码。
读取当前项目规范、相关任务、模块基线、源码、接口和配置，记录dirty基线。区分用户要求与当前事实，发现不符登记缺陷，不降低标准迎合旧实现。
画清真实用户入口→Vue事件/状态→领域API→Python校验/Service/Repo→数据库或任务→结果回读，以及涉及的Tauri命令、Sidecar、配置和资源释放。覆盖实际存在的编辑/试跑/正式/恢复入口，标明唯一事实源、稳定身份、写入责任和外部隔离边界。
形成可观察R标准、方案取舍、影响范围、依赖顺序、迁移/回退、异常路径和验证矩阵。批量写必须一次提交服务端，接口缺失列为后端工作；不要规划前端循环或分片写入。
按五维评估复杂度L1～L5并关联计划版本，整体取最高维度，风险和工作量另列。小任务合并记录，不造空文件。
交付架构/方案、事实与待查项、复杂度及“可进入实施/待具体决策/待核实”的结论；提供下一阶段完整text提示词，不把方案通过写成实现或验收通过。
```

## 03 检查实施计划

```text
使用 $python-vue3-tauri-guide，检查任务〈任务号〉的〈计划路径与版本〉及关联复杂度记录。本次只检查计划，不重设计、不改业务/测试代码，不为计划检查运行整套测试。
核对用户目标、成功标准、非目标和已有授权，确认准确路径/命名、真实调用入口、依赖、三端和迁移联动、配置事实源、R编号及验证边界。验证命令必须存在并有工作目录、输入、通过标准、环境和外部替换范围，不能只有“测试通过”或待猜脚本。
涉及批量写时核对一次前端提交、完整服务端契约及两侧证据；涉及页面、Sidecar或数据库时核对相应生命周期和失败语义。核对五维复杂度、计划版本和实际未知项，检查开发、复核和人工验收职责。
把具体缺项与依据写入本任务记录，结论只给“计划检查通过”或“待完善”。已存在执行授权时不重复索要确认；没有缺项不扩充无关任务。
```

## 04 执行开发、自检与交接

```text
使用 $python-vue3-tauri-guide，执行任务〈任务号〉，需求/计划为〈范围与计划路径〉。本次授权阶段：〈开发交接 / 开发并复核 / 已授权的完整阶段〉。
恢复现行规范、唯一计划、计划版本和R标准，记录实际dirty基线、已有授权与非目标。计划未细化时先补准确文件/公开命名、契约、依赖顺序和验证矩阵；用户已要求执行的范围直接推进，不为普通实现细节重复审批。
按实际依赖实施后端校验/业务/持久化、类型化API、Vue页面与必要Tauri/配置/迁移联动；沿用真实公共组件和唯一事实源。缺陷先保存可复现输入与预期，不只修症状。所有批量写一次提交服务端，缺接口先实现。
完成相称自检和计划内复杂验证，至少跨越本次最易断裂的真实内部边界；外部可隔离但标明范围。保存真实命令、退出码、业务回读、受测源码/配置身份及R对应E证据。本轮新增问题和阻断目标的旧问题先修复，不降低规则过检查。
日常不自动生产构建或全仓格式化，不操作无授权现役环境。只重验受新变更影响的证据。开发完成复评复杂度，提供每个后续检查的环境、命令/操作、输入、通过标准、已有证据与失败返回。
完成本次所有已授权阶段；独立交接边界按用户要求保留。最后报告实现范围、已做/未做验证、复杂度、未关闭项、交验状态和完整接续text提示词，不替用户确认验收。
```

## 05 Vue 页面与交互增量开发

```text
使用 $python-vue3-tauri-guide，完成〈页面/路由〉的〈具体变化〉。先读目标页面、同类页面、领域API/类型、公共组件和UI规范，保留本次范围外的正确逻辑与已有改动。
先确定真实组件和样式所有权，沿用现有页面骨架、查询/表格/浮层和请求层；不复制第二套公共组件、状态机、字典或全局样式。新增字段同步DTO、类型、校验、查询/重置和保存回读；0/false/null/空值保持协议语义。
使用稳定ID处理选择、展开、行操作和批量；批量一次提交服务端。覆盖加载、空态、异常、取消、重复点击、失败保留草稿和成功刷新。核对本次所有浮层的真实外壳事件、完全关闭/重新打开及已有的收起恢复，不能用内部表单替身证明外壳合规。
布局遵守项目现行滚动方案；主列表若要求内部滚动，验证真实表体滚动、表头/底部分页位置和外层几何，覆盖适用窗口尺寸、查询展开、页签、横向滚动及窄屏，不只检查class名。
按范围运行类型、相关交互及格式/样式检查。临时Vite验证隔离端口和cacheDir；截图遵守当前授权且不代替数据断言。记录真实请求/回读与未覆盖原生或外部环境，日常不自动生产构建。
```

## 06 服务端批量功能

```text
使用 $python-vue3-tauri-guide，为〈领域/页面〉实现〈批量操作〉，遵守服务端批量契约。一次用户确认必须只发送一次批量写请求，携带完整稳定ID集合与参数；禁止前端for/forEach/map/Promise.all/并发池或分片调用单项写接口，没有接口就补齐后端。
先确定真实端点、ID类型、白名单、非空与单次上限、去重/计数规则、权限/当前状态/关联限制及审计。超限明确拒绝或设计一次提交的服务端任务，不能客户端分片。按领域选择整批事务或逐项独立部分成功，明确成功/失败/跳过及逐项原因；涉及外部副作用时不能假称数据库事务能回滚第三方。
按Route→请求模型→Service→Repo实现，允许后端内部逐项复用已有业务方法。长任务返回真实任务标识和状态；幂等/重试/取消按实际副作用设计，前端不制造逐项进度。
验证多选一次确认仅一次完整批量请求、取消零次，以及真实后端到隔离数据库的校验/写入/回读。覆盖空/超限/重复/非法/缺失ID、状态/权限/关联限制、所选提交语义、结果计数和审计。不能只测按钮或mock整个Service。
交付两侧R/E证据、事务和错误语义、真实命令/退出码、未覆盖外部边界，保持界面结果与服务端一致。
```

## 07 Tauri 与 Python Sidecar 联调

```text
使用 $python-vue3-tauri-guide，处理〈桌面启动/原生能力/退出/配置问题〉。先核实Tauri/Rust/插件版本、开发与发布脚本及Python托管方式，不新增平行监督者或复制业务逻辑到Rust。
梳理配置事实源→Python/Vue/Tauri派生配置→Sidecar进程参数→健康就绪→窗口可用的真实链路；数据目录和应用版本只有明确所有者，生成文件不手改，消费者已保存设置不被启动默认值覆盖。
核对开发解释器与发布二进制路径、Sidecar架构/命名和资源声明；启动检查子进程退出、超时、端口冲突及本次服务身份，不因端口可连就认定就绪。失败给出可理解错误。
启动失败、重载和退出仅回收本应用拥有的进程树，不接管或终止未知占端口服务；需要时复用Windows所有权/Job机制。数据库迁移/恢复前遵守既有同库服务所有权锁，不把它变为所有业务SQL串行锁。
在隔离环境覆盖正常启动、健康失败、端口冲突、子进程异常、退出收尾及本次相关原生命令；网页Vite通过不等于Tauri能力已验证。按授权范围完成测试，真实生产构建只在本次明确要求时执行。
记录实际运行源码/配置、进程所有权、命令/退出码与剩余原生/安装后边界。
```

## 08 数据库变更与恢复验证

```text
使用 $python-vue3-tauri-guide，处理任务〈任务号〉的〈结构/数据变化〉。读取现有迁移工具、当前/目标版本、数据库归属和备份政策，不创造不存在的stage/accept/merge命令。
明确表字段/索引/约束/种子/转换、业务数据影响及配套源码回退，联动Repo、DTO、前端类型与受管契约。使用项目环境和隔离库，不热改现役库。已执行迁移ID/摘要/顺序及已发行包不可重写，修正新增步骤。
变更前准备可恢复的完整原始备份，SQLite WAL不以仅复制主db当作完整备份。隔离验证新库初始化、旧库升级、重复启动不重放、失败事务/台账回滚、结构契约、数据语义、完整性/外键与备份恢复中的适用项。
采用开发中转时，将变更登记到正确未发行目标，开发验证后锁定摘要待验收；自动测试不代替人工通过，不擅自accept/merge/freeze。用户已明确确认的范围按证据完成已授权合并，保留原步骤身份，按前置顺序处理，不重放SQL。
报告迁移身份、所属版本、真实命令/退出码、备份与恢复证据、未覆盖路径及当前验收/合并状态。无数据库变更的范围不造空迁移。
```

## 09 独立自动复核

```text
使用 $python-vue3-tauri-guide，复核任务〈任务号〉，以〈当前计划版本/复核任务路径〉为准。本次只复核，允许更新证据、复核状态、缺陷和验收清单，不修改业务、迁移、测试逻辑或成功标准以制造通过。
先核对用户是否已明确人工通过；只将确认范围标记为被人工验收覆盖并转结案，保留未执行/失败历史，不补造自动通过。未覆盖范围继续复核。
核实dirty源码/配置/依赖身份、计划R标准、命名与引用、真实调用链及已有E证据时效；先复用有效证据，再执行交接中的待做检查。缺环境写未验证，不靠测试总数、API200、静态class或宽松mock替代业务结果。
逐项保存工作目录、真实命令/操作、退出码、断言、回读和隔离边界；失败按开始基线具体归因。内部保存、装配、参数、事务和回存问题写缺陷交开发，不改名为人工验收项；需要核心修复即交接，不凑固定重试次数。
核对批量请求次数及服务端真实链路、UI真实外壳、Sidecar/数据库路径中实际适用项。截图按当前授权，不机械重跑整套测试或生产构建。
先列覆盖、失败和未验证项，再给当前唯一“可交验收/有条件可交验收/不可交验收”。有条件项写具体影响和用户接受依据，未接受的偏差仍待决策。只有放行范围进入待人工验收，附具体交接text提示词。
```

## 10 修复复核发现的问题

```text
使用 $python-vue3-tauri-guide，修复任务〈任务号〉的〈失败记录/检查ID〉。恢复计划、开始基线、当前diff及原失败输入、断言与E证据；本次授权修复及相应回归。
先定位共同根因和原检查为何漏掉，核查真实内部接线、参数/值类型、唯一事实源、状态/生命周期及外部替身边界。不能删失败样例、mock掉故障边界、改标准或扩大排除范围过检查。
只改必要实现与受影响调用方；若范围/技术路径/契约/验证方法实质变化，更新唯一计划版本、复杂度和后续复核任务，普通状态更新不造新版本。批量问题同时核对一次请求和完整后端契约。
补能复现旧失败的业务证据，验证修复结果、关键副作用和适用回归，只重验受影响项。分别保存真实命令、退出码、源码/配置身份和未覆盖环境。
关闭项必须有复核依据，仍阻断目标的旧缺陷继续处理；需要用户决策/外部条件时列具体证据和已尝试方法，独立可做部分继续。交付修复点、根因、漏检原因、有效证据与接续复核提示词，不提前宣称用户验收通过。
```

## 11 生成人工验收清单

```text
使用 $python-vue3-tauri-guide，为任务〈任务号〉整理可执行人工验收清单。依据当前计划、最新复核结论和实际实现，不替用户勾选通过，也不修改业务来迎合清单。
先核对已明确人工通过的具体范围，归档其原标准/确认依据；其余范围按实际交验资格登记。未达到门槛的标准备中/待复核/内部修复中/待决策，不引导用户验收内部缺陷。
按真实依赖排列：备份/部署/迁移/重启/配置准备与就绪→基础能力→业务链路→相关回归。每项给R编号、版本、前置、数据、从真实入口开始的操作、可观察预期、失败反馈和恢复方式。
覆盖本次需要的真实外部授权、原生命令和人工体验；保存/参数/装配/回存等内部可复现错误应交开发修复。清单与已有待办冲突时更新受影响旧标准，不能保留互相矛盾的要求。
```
