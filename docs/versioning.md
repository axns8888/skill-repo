# 技能版本管理

本规则适用于 `skills/<技能名称>/SKILL.md` 定义的每个独立技能。仓库当前 10 个技能统一从 `1.0.0-rc.1` 开始管理；此前零散的版本标记按本次要求统一归入这个源码基线，不据此追写历史发布。嵌套模板和脚本说明随所属技能升级，不单独分配技能版本。

## 版本来源与记录位置

- `SKILL.md` frontmatter 的 `metadata.version` 是技能版本来源，使用带引号的字符串。保留同一 `metadata` 下已有的其他字段。
- 每个技能的 `README.md` 展示当前版本，并在“版本管理与记录”中保留历史，最新记录置顶。
- 仓库根 `README.md` 的技能列表展示各技能当前版本，更新时须与对应元数据一致。

示例：

```yaml
metadata:
  version: "1.0.0-rc.1"
```

## 升级规则

版本采用 `MAJOR.MINOR.PATCH`，预发布追加 `-rc.N`。各技能独立升级，不要求全仓库版本始终相同。

| 变化 | 版本处理 | 示例 |
| --- | --- | --- |
| 同一目标版本发布前的后续修正 | 增加 rc 序号 | `1.0.0-rc.1 → 1.0.0-rc.2` |
| 目标版本达到验收要求 | 去除预发布后缀 | `1.0.0-rc.2 → 1.0.0` |
| 正式版后的兼容修复、无行为变化的文档修正 | 增加 PATCH | `1.0.0 → 1.0.1` |
| 兼容的新增能力或可选规则 | 增加 MINOR，PATCH 归零 | `1.0.1 → 1.1.0` |
| 不兼容的配置、调用方式或默认流程变化 | 增加 MAJOR，MINOR/PATCH 归零 | `1.1.0 → 2.0.0` |
| 下一目标版本先行验证 | 使用目标版本加 `-rc.1` | `1.0.0 → 1.1.0-rc.1` |

修改一项技能只升级该项；依赖技能也有实际改动时才升级其版本。涉及跨技能协议或配置兼容性时，在相关记录中写明依赖版本及迁移要求。一个尚未交付的变更批次可沿用该批已分配版本完善内容，不按文件或每次保存累加版本；后续独立变更批次应递增。已经发布的版本不可用不同内容覆盖。

## README 记录要求

每条记录包含版本、实际变更日期、具体改动和验证结果。影响兼容性时写明旧用法、新用法和迁移操作；较长说明可链接同技能内的文档。记录实际发生的结果，区分静态检查、自动测试、模拟验证与平台实测。尚未进行的验收写明待验证，不因填写版本或更新锁文件宣称验收通过。

`1.0.0-rc.1` 的记录表示现有技能内容纳入统一版本管理。记录中的“本地源码基线”不代表已发布、已安装或完成真实平台验收。历史记录保留当时状态；后续发布事实可追加发布说明。

## 本地更新步骤

1. 确定实际改动的技能及目标版本。同步更新其 `metadata.version`、技能 README 的当前版本与最新历史记录、根 README 的版本列表。
2. 检查三处版本一致、版本记录完整，并运行与改动相符的验证。
3. 运行 `npm run skills:lock` 更新所有技能的内容快照，再运行 `npm run validate` 完成仓库检查。验证结果写回 README 后如改变技能文件，需再次更新快照并核验。
4. 按 [本地开发与跨电脑复用](local-development.md) 的流程处理后续同步与发布。源码版本更新不自动安装、不自动创建 tag，也不自动远程发布。

`skills.lock.json` 的顶层 `version` 是锁文件格式版本，其 SHA-256 标识具体文件内容；两者均不替代技能版本。Node 版本描述运行环境。现有 `skills-vYYYY.MM.DD.N` 仓库 tag 标识一批已验证的源码提交，可以同时包含多个不同版本的技能；无需为本次技能版本规范更改仓库 tag 格式。
