## Decision principles
- Narrow views only serve defined workflows and preserve complete output as the default.
- Reuse facts only with known source and relevant preconditions; recheck after code/config/branch/permission/executor changes or explicit expiry.
- Classify failures as input, authorization/conflict, transient platform, or unknown outcome. Retry only when non-start/idempotency is certain and preconditions remain unchanged. Waiting records its subject, start time, and resume condition; never redispatch an unknown-running task.
- Snapshot creates recoverable material and a receipt only. It does not set acceptance/completion/finish/archive state and does not delete the source worktree. After restore verification, the original task coordinator/authorized user decides migration or retirement.
- Evidence review found no concrete use case supporting unaccepted aggregation, no-worktree auto-close, or additional platform adapters. Record no expansion this batch.

## Generic project-guidance follow-up
- The project-specific usage/coordination policy belongs to each target project, not the reusable skill repository. `_plan/project/` is a project-owned extension point alongside (not a replacement for) `_plan/prompts/project.md` and the project's `AGENTS.md`.
- Seed templates are explicitly pending project verification. Mentioning or installing a skill/tool is not evidence it is available or enabled. Skill-generated project policy must retain its evidence and review status.
- No separate `constraints.md` is generated by default: existing project baseline sections already cover stable constraints, and a duplicate file would create another competing source. Projects can add such documents when a real need arises and index them in `_plan/project/README.md`.
- Current-repository acceptance showed generic initialization is safe to run in a non-empty real repository when preflight confirms preservation.
