# Axns8888 skill-repo开发基线

仅保留当前项目需要的章节。已有等价规范时增量补充，不维护第二份同义基线。填写可核实事实；未知项给出核实动作。技术栈填写项目实际选择，本模板不预设语言、框架或应用形态。

## 流程目录与入口

新项目先建立完整最低目录骨架，见 [目录与初始化](../guides/project-layout.md)。业务源码和工具目录按实际技术栈确定。

- 项目资料：`_doc/README.md`；子目录 `demos/`、`scripts/`、`使用说明文档/`、`第三方插件文档/`。
- 开发流程：`_plan/README.md` 与 `_plan/flow.md`；子目录 `future/`、`guides/`、`ledger/`、`process/`、`project/`、`prompts/`。
- 项目自有技能使用方式、工具协作和补充约束：`_plan/project/README.md` 索引；不在此重复维护，技能或扩展未被项目明确启用时不得推断其生效。
- 当前基线与可复制指令：`_plan/prompts/project.md`、`_plan/prompts/stages.md`；通用阶段规则与模板：`_plan/guides/`。
- 任务计划与证据：`_plan/process/`；台账与验收归档索引：`_plan/ledger/`；延期事项：`_plan/future/`。
- 已有等价载体及映射：本轮活动计划由 `.planning/.active_plan` 选择，详见 [_plan/project/coordination.md](../project/coordination.md)；同一任务不复制到 `_plan/process/`。未来如迁移计划入口，需明确归档旧记录并停止双轨维护。

## 目标与边界

- 产品目标、用户或调用方、核心场景：维护、验证并分发本仓库的 Agent Skills 源码及辅助工具。
- 当前阶段、本期范围、成功标准、非目标：按当前 `.planning/.active_plan` 指定任务执行；不将技能仓库等同于其使用者的业务项目。
- 运行与交付环境及兼容要求：Node.js 版本以 `.nvmrc` 与 `package.json` 为准；技能兼容性另按各技能声明验证。
- 现行规范、任务索引与相关决策：`docs/`、各技能 README/SKILL、`_doc/skill进化树/` 与活动计划。

## 工程规范与交付深度

- 交付深度与本期可用范围：按技能声明的真实使用场景交付；文档/静态检查、自动测试与平台实测分层报告，不将未执行验证写成通过。
- 架构与实际源码树：[架构规范](architecture.md)；现行等价入口：〈有则映射〉。
- 命名、注释、类型和错误处理：[编码规范](coding.md)；现行等价入口：〈有则映射〉。
- UI 布局、令牌、公共组件和状态：[UI 规范](ui.md)；无界面注明不适用。
- 工程要求如何执行：[建立与执行规则](../guides/engineering-standards.md)。实现前将上述文档具体化到本项目；新增文件包括提示词未点名的实现均按同一架构落位。
- 本期模块完成矩阵：由当前活动计划按具体改动维护；不在稳定基线复制任务状态。
- 首个贯通的真实模块及证据入口：技能目录的 `SKILL.md`/README → 对应脚本或提示词 → `tests/` 与使用者项目验证，按具体技能适用。

## 模块、依赖与命令

| 模块或工具 | 职责与实际入口 | 配置、版本或锁定依据 |
| --- | --- | --- |
| 技能源码 | `skills/<name>/` | 各技能 `SKILL.md`、README、脚本及引用 |
| 本地维护工具 | `scripts/` | `package.json` 与脚本源码 |
| 自动测试 | `tests/*.test.cjs` | Node 内置测试运行器 |
| 文档和技术栈模板 | `docs/`、`templates/`、`_doc/`、`_plan/` | 各自 README 与当前项目基线 |

| 动作 | 工作目录 | 已核实命令或操作 | 环境及数据前置 |
| --- | --- | --- | --- |
| 定向测试 | 仓库根目录 | `node --test tests/<相关文件>.test.cjs` | Node 版本符合仓库要求 |
| 更新技能快照 | 仓库根目录 | `npm run skills:lock` | 技能源码修改后 |
| 校验技能快照 | 仓库根目录 | `node scripts/skills-local.cjs verify` | 不替代自动测试 |
| 全仓验证 | 仓库根目录 | `npm run validate` | 更新快照后执行，包含全量测试 |

未执行的命令不作为验证证据。只列项目存在且当前需要的动作。

## 关键边界与契约

- 实际入口 → 处理 → 结果及适用副作用：`package.json` 命令或技能入口 → `skills/`/`scripts/` 实现 → 测试和生成物；同步命令会修改本机技能目标，应单独按授权执行。
- 模块职责、公共能力及复用入口：见根 README 技能索引、`skills/` 子目录及 `docs/local-development.md`。
- 适用的架构、前端、接口与发布专题规范：通用工程见 `docs/`；前端/接口仅在具体技能适用时按对应技能文档读取。
- 适用的输入输出、状态、错误、数据或兼容约定：〈内容〉
- 配置与共享状态的事实源、消费者、生效方式：根 `model-routing.json` 为本仓库模型路由表；`skills.lock.json` 为技能内容快照；本机安装状态按 `docs/local-development.md` 管理。
- 适用的资源创建、使用、恢复与释放责任：〈内容〉
- 外部依赖、可隔离边界和受管环境：仓库以 Node.js 辅助脚本和内置测试为基础；外部平台/Agent 环境属于适用技能的单独实测边界。
- 生成物、允许写入范围及需保留的已有数据：按任务范围改动技能源码、测试、文档和锁；保留其他未提交工作及本机配置，不提交凭据或平台私有状态。

## 工作流与质量

- 任务与现行计划、事实、证据、复核和结论入口：本轮 `.planning/.active_plan` 指向的目录；稳定约定在本基线及 `_plan/project/`。
- 角色、交接边界及当前授权：按用户任务授权；执行者只写入其任务范围，独立复核与交付门禁按 devflow 阶段指南执行。
- 默认按任务规模组织流程：小改动可在现有记录或回复中交付；已有执行授权继续有效。需要先汇报等待确认时，由用户明确指定。会话可复用，任务身份、目录和执行权每次重新核实。
- 成功标准与证据关联方式：每项结论关联实际命令、测试统计或明确的人工验收记录。
- 必要检查、证据身份与失效判断：以当前源码 HEAD、测试命令及结果为证；源码或配置变化后重跑受影响验证。
- 人工验收策略：唯一入口 `_plan/prompts/acceptance.json`，默认关闭；开关语义见 [人工验收配置](../guides/acceptance.md)，不在本文件重复定义。
- 启用时的确认范围、反馈入口及台账归档位置：人工验收默认关闭；按实际发布/使用任务另行明确。
- 结案、发布及过程记录保留方式：源码任务结论写入任务计划和技能版本记录；同步、提交、打 tag 和远程发布分别授权。

## 编程器与 IDE 协作

接入分工与流程见 [工具协作](../guides/tool-integration.md)，以下仅记录本项目选择。

- 主要执行平台及已核实版本：仓库源码主要在 Git/Node 环境维护；DSH、Orca 等平台版本和账号状态待具体环境核验；本仓库未声明自动唤醒入口。
- 原生清单沿用项目 task-id 并组织当前阶段步骤；范围、成功标准和证据入口仍以原任务计划为准，不重复维护清单历史。
- IDE 按维护者环境使用；项目命令统一依据本基线与 `package.json`，切换执行者前协调现有写入权。
- 跨平台先结束原派发再切换唤醒入口；启用 autopilot 时以 owner / dispatch_id 和 request.cwd 为准。平台投递或清单完成不等于任务验收。

## 任务窗口与可选扩展

- 本轮沿用 `.planning/.active_plan` 及其选定任务目录；不要在 `_plan/process/` 重建同一活动计划。新任务记录载体需按项目现状明确选择。
- 可复制的窗口协议从 [P0 开窗](window/P0-open.md) 开始，P1–P4 共用，P5 仅 worktree 扩展启用时使用。
- 仓库根无 `AGENTS.md`，没有声明启用 worktree/autopilot；不得仅凭扩展源码存在而推断已启用，不创建相应运行状态。
- 修改后提交/同步/发布各自依用户明确授权和 `docs/local-development.md` 执行；常规验证不隐含同步技能副本或创建发布标记。
