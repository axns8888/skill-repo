# P0 开窗：读取并回报

此入口用于正式启动或需要重新建立现场的接续。状态查询和只读诊断直接检查当前事实；轻量项目维护先核实配置所有者及冲突，勿为此登记业务任务。已派发执行者优先用工单的 cwd、HEAD、范围、已有路由与计划/证据入口，在读取适用指令后只补核未确认或已失效的事实。

主协调者维护全局目标、依赖、唯一权威计划和整合决定，可跨会话接续；其身份不由分支名决定。集成分支是本批派发时核实并固定的目标基线；任务 worktree 是一个明确交付目标的执行现场，可容纳该目标下有限连续步骤。执行者仅使用分配的 task-id、cwd、授权、scope 和活动派发，不另建全项目计划或重复登记。切换执行者时复用原任务和工作区，并先完成真实停写/交权；接续后重新核实受影响事实，不继承上一执行者的身份或回调。

已有任务直接恢复现行记录，不重新登记；普通小改动且不需要正式登记时，按宿主轻量流程完成，不为使用本提示词创建任务目录或活动指针。已纳入 autopilot/worktree 的任务继续遵守其登记与回调协议。

按序读取：适用的 AGENTS.md → 项目基线中与本目标相关的规范 → 原唯一计划/活动任务索引 → 当前执行者和持权 → 本次必要的源码与工作区状态。已登记执行者使用派发材料和摘要，只核对未确认或失效的事实；不重读全项目历史或无关计划。Git 项目在写入/提交检查点核实 `git status`、暂存及未暂存 diff；非 Git 项目核实当前目录、相关文件和已有变更，不把缺少 Git 当成阻断。路径和记录映射以权威计划及项目基线为准。

工作区模式仅取项目 AGENTS.md 的 `extensions` 是否包含 `worktree`；autopilot 单独按其开关与执行配置核实，不要求同时启用 worktree。未启用时读取 `_plan/.active_plan`；启用时先加载 axns-devflow-ext-worktree，按其协议定位**主检出目录**的 `_plan/active/`、`_plan/registry.jsonl`，不要读取任务 worktree 中过时的副本。没有 active 目录时检查旧单指针，并报告迁移状态，不自动切换模式。

先读取并简短回报以下适用信息；核实期间不修改文件，之后按已有授权继续。长阶段按可验收短工单执行；协调窗口只保留状态和证据索引，达到可见预算或保守轮换边界时，先落盘并停止写入，再由新会话核实身份与接管：

- worktree 扩展：是 / 否；配置依据与共享控制目录绝对路径。
- 活动任务：task-id、状态、依赖及占用；无记录如实说明。
- 本窗口任务：{{任务描述}}。
- 模式：单任务 / worktree 隔离。
- 扩展启用时：初步 scope、shared_claims、depends_on、owner。
- 工作区已有变更、尚需确认的项目决策。
- 上下文预算：可见剩余量/压缩信号或“未知”，评估是否可在当前执行者内连续完成有限任务链；仅在恢复成本、上下文或授权边界要求时拆窗。按 [上下文预算与交接](../../guides/context-handoff.md) 核实原记录与执行权，不因换窗再建 worktree。
- 需要跨工具时：DSH/Orca 安装与实际可调用条件、用户允许的平台和并发范围；缺少可选执行端时使用当前可用工具，指定平台或独立复核不能完成则如实保留待办。

全程不变量：

1. 正式登记任务的计划、执行证据、复核与当前结论位于同一 `_plan/process/<task-id>/`；轻量任务可在现有载体或交付回复中合并说明。
2. 证据来自实际命令、测试和 diff；未执行不能写通过。
3. 复核区分阻断项与建议项；阻断项关闭前不进入验收。
4. 验收通过前不合入集成分支；冲突只在任务分支处理。
5. 已进入 worktree 隔离的任务使用独立目录和分支，scope 不相交，共享文件修改权互斥，提交以 `<task-id>:` 开头；协调职责不取决于当前分支名。
6. 手动跨窗口接续核实原任务记录、实际工作区和执行权交接；同一 task-id 不提供同步或互斥。扩展启用时按其协议读写共享登记文件，不靠人工转述代替登记事实；事实仅在来源版本及前提未变时复用，HEAD、工作区、配置、权限、分支、执行者或等待状态变化时重新核实。

用户已授权执行时，回报后继续当前所需阶段，不重复等待开窗确认。用户明确要求“先汇报，等我确认”时，或缺少必要授权、关键决策时，只等待受影响的动作；仅要求盘点时以回报为交付。

autopilot 中 P0 完成使用 `--user-confirmed` 声明已核实适用的执行授权，证据写明原指令或可追溯位置；已有授权即可作为依据。若用户明确要求本次回报后确认，必须等该确认，不能用更早的授权替代。该标记不代表人工验收通过。

新登记任务进入 [P1 登记](P1-register.md)；已有任务直接恢复其当前阶段。
