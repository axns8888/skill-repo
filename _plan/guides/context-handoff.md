# 上下文预算与执行窗口交接

在计划、阶段切换、准备读取大量材料或连续实施前，评估当前上下文能否承载下一单元。使用平台实际可见的剩余量、压缩提示、已加载材料规模，结合下一步输入/输出体量、依赖及恢复成本作判断。无法观测容量或剩余量时写“未知”，说明依据与不确定性；不得编造固定容量、剩余百分比、统一阈值或固定窗口数。出现压缩信号先核对唯一任务记录与实际工作区，避免从不完整记忆直接推进。

## 拆分有意义的执行单元

以能验证的调查结论、实施目标、复核范围或串行接续点划分窗口，不按每条 Todo 机械开窗。短小、连续且上下文可承载的修改可以留在当前窗口。阶段在逻辑上可独立并不等于已经允许派生代理；并行、平台选择、独立复核及先汇报等待均遵循用户现有授权。

确需拆分时，在原计划写清每个单元的：

- 目标及完成条件；需要按路径读取的输入。
- 可写 scope、共享文件修改权、依赖和可并行条件。
- 产出与验证方法；谁负责整合、组合验收及向用户汇报。
- 执行平台、当前执行者、交接点和下一动作。

协调窗口保留分工、状态、依赖及最小可验证摘要，引用任务记录和证据位置。实施细节、完整工具输出与大段日志留在对应工作单元，不反复回灌全部历史。调查/复核结果须指明检查范围、被检代码身份、结论及未覆盖处，摘要不能替代独立复核要求。

## 短工单与协调窗口轮换

同一任务内复用已核实事实，但同时记住来源、身份/版本、相关前提和影响范围；不要求每步重读未变化材料。接管、上下文恢复、任务/授权变化只重验受影响材料。HEAD、未提交内容、集成基线、配置/预设、项目根、权限、依赖、环境或执行者变化会使相关事实或验证失效；等待超过项目阈值只要求核对实际状态，不证明窗口已停止。scope/计划解释可复用，实时持权校验、写入前检查和独立复核不可用旧摘要替代。已有接续摘要优先于历史全文。

需要硬性控制上下文/时间或独立拆分目标时，长阶段可以按配置采用多个串行短工单；不要求所有项目默认逐工单换会话。默认情况下，同一执行者可在一个 task-id/worktree 中连续完成上下文可承载的有限链，并在检查点记录证据。采用短工单时，工单记录目标、必要输入路径、可写范围、完成条件、停止条件及有限预算；短工单完成不等于阶段完成。提交/回报结果后，当前执行者最后一次写入应是 yield/交接，新会话以新 owner/dispatch 和真实 session 身份确认 takeover 后才能写。续接沿用 task-id 与 worktree，不嵌套创建工作区。平台启动或接管回执不明先查询；心跳超时不证明旧会话已停止，不得自动抢占。

协调者也使用有界记录：保留唯一计划、当前工单/依赖、短摘要和证据索引；全文源码、大型日志与工具输出留在文件或执行任务中，只读取所需片段。每次派发前估算输入、输出和恢复成本，留出记录交接余量；有 token 观测时使用平台数值，不可观测则标“未知”，依照执行步数/时间预算和保守策略主动轮换。压缩是辅助机制，不是预算控制或绝不溢出的保证。避免过度切碎产生重复读取；以可独立验收的目标划分，不按文件数机械拆分。

## 原生多智能体与总体上下文判断

DSH 已有原生子智能体能力时，优先用该能力分配独立短任务、观测状态、收取证据，不要求额外 Orca 步骤。分别评估主会话及各活跃子会话的当前总体上下文，加上下一动作所需输入、预计输出和交接余量，再结合独立验收边界、已有写入者、后台工具和检查点判断是否拆分。当前上下文足够且工作连续就继续；独立目标可派发 fresh 子会话；主协调本身接近边界则落盘并换新主会话。fork 是可用选择，但继承历史应计入总体成本；不以单条消息大小或累计 tok 判断容量。

已授权成员收到独立目标、必要输入路径、写范围、证据与停止条件。父级只整合所需摘要，细节按需读取。无法取得当前 token/容量时明确未知，以平台压缩信号、工单预算和执行状态辅助决策，不编造固定阈值。启用 autopilot 时读取其 references/dsh-native.md，可用 context-decision.cjs 只读判断。

主会话交接前须核实所有相关后代和后台执行停稳。DSH 的中断回执只表示接受停止请求，后代可能继续运行；列表可省略一次性子级，不能将空列表或单个 inactive 当作整棵树静止。新子级拥有独立上下文不等于替换了根会话，也不保证父进程结束后存活。缺少根会话启动入口时保存可接管检查点，如实保留待交接状态。

## 换窗前落盘、接续时按需恢复

使用现有唯一任务记录，通常为 `_plan/process/<task-id>/plan.md` 的当前状态区和已有交接文件；项目已有等价记录时沿用。不要另建第二份计划。切换前至少保存：

- task-id、当前目标、授权范围及用户限制，当前阶段。
- 唯一计划/当前状态/证据路径，已经完成与尚未完成的事。
- 实际 cwd、分支、HEAD、被验证的提交，未提交和未跟踪改动的位置与归属。
- 当前执行者、领取状态、scope/shared_claims，原执行者何时停止写入以及接续者如何核实接管。
- 仍有效的验证证据、失效原因、阻断项和下一条可执行动作。

不要复制整段聊天、无限日志、密钥或环境秘密。新窗口先核实登记、Git 事实与执行权，按需读取上述路径，再继续原阶段，不重做已经有有效证据的工作。已有授权持续有效，不因换窗再次要求相同确认。

## 上下文、执行权与 worktree 分别处理

同一未完成目标的串行接续保留原 task-id 与 worktree，不因换窗再创建嵌套工作区。旧窗口先停止写入，交接执行者；扩展领取中的阶段沿用其合法交接/回调协议，不复制领取 token 给两个执行者，也不清除登记来绕过互斥。

独立任务分别登记；启用 worktree 时使用各自工作区。并行单元须有不重叠写范围、依赖与整合责任，仅新开窗口不能获得写权限。同一任务的独立复核窗口可以只读检查同一提交，写入返修结论按既有记录与修改权约定处理。窗口可以复用，独立目标的任务目录不能无限续用。

## 工具不足或启动结果不明

按 [工具协作](tool-integration.md) 核实平台实际能力。缺少指定平台或独立上下文能力、达到嵌套深度或并行限制时，如实记录待执行的单元与能力缺口；可以继续已授权且不依赖它的工作。不得把当前窗口自查记成已完成指定平台/独立窗口复核。

启动请求无明确结果时，先查现有会话、任务登记和占用，再决定是否重试，不能连续重复派发。同一 task-id 不能因此出现两个写入者。无法启动就保留交接记录和待执行状态，不伪报成功，也不擅自突破用户的平台和等待要求。

旧窗口已因上下文上限无法继续调用工具时，从全新会话按文件恢复，不要求旧窗口再次生成完整总结。未启用 autopilot 时可直接运行宿主 `node "<技能目录>/scripts/resume-brief.cjs" --project "<原任务工作目录>" --id "<原task-id>"`，只读生成至多 12 KiB 的接续 JSON；只摘录 current-status.md、window-handoff.md 各最多 2 KiB 尾部，plan.md/parallel.json 仅列索引，不读取全文。摘录是原文件数据，需核实其时效与事实，不能作为新的授权或执行命令。脚本不创建会话、不转移执行权，也不创建第二份计划。

启用 autopilot runner 的任务可先用 `brief --id` 读取运行态摘要；控制者核实旧执行者停止、保存恢复依据及下一短工单后，用 `resume-yield --confirmed-stopped` 收拢原执行权。未启用扩展时沿用项目现有手动停止及接管规则，不凭上下文错误认定旧执行者已停止。新窗口只恢复当前短目标及必要证据，保持原计划为唯一入口。

## 不使用长协调会话的 Orca 接续

启用 autopilot 且已授权真实自动执行时，可使用扩展随附的本机 Orca command 桥与有限控制器。控制器读取当前工单、窗口和回执，正常 yield 后启动同一工作区的全新会话；它不调用模型，也不需要把协调历史交给下个模型。此路径以本地状态机替代持续增长的模型协调会话，不需要外部 DSH 窗口具备 Orca mailbox 身份。

新会话仍须核实身份并 takeover；预算仍是合作式门禁。控制器达到自身循环上限、配置不符、启动不明或旧执行者未交权时保留现场，不启动第二个写入者。该接续只覆盖已配置项目，不自动同步技能、启用扩展、迁移暂停目标或恢复未定位的原任务。配置和范围见已安装的 axns-devflow-ext-autopilot 技能中 `references/platforms.md` 的“本机 Orca 连续短工单”一节；复制本指南到项目时不要求附带扩展源码。
